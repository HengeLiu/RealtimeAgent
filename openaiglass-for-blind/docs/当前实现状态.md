# 当前实现状态

本文按当前代码整理，目的是让开发人员先知道真实运行面，再阅读阶段文档。更新时间：2026-04-26。

## 总体结论

当前仓库已经拆成两条主线：

1. [../../openaiglass-sdk](../../openaiglass-sdk)：三端 SDK 框架，承载服务端运行时、协议、公共模型、Tool/Task/Skill、测试工具和 SDK 文档。
2. [..](..)：盲人 AI 眼镜真实场景工程，承载 `find_object` 业务能力、iOS 手机端、ESP32 眼镜端、业务场景数据和联调脚本。

服务端真实实现已经迁入 SDK：

1. [../../openaiglass-sdk/python/app/main.py](../../openaiglass-sdk/python/app/main.py)：SDK 内真实服务端入口，承载 HTTP、控制 WebSocket、音频 WebSocket 和运行时装配。
2. [../server/main.py](../server/main.py)：盲人业务服务端入口，通过 `OpenAIGlassesSDK` 注册 `find_object` Tool、Task、PhoneProcessor 和 PhoneTask。

## 需要注意的真实边界

1. 普通对话路径虽然使用流式模型接口，但普通文本 delta 不是完整端到端透传到 TTS 的真流式；图片解读和部分回调路径更接近流式体验。
2. 单次抓拍当前是控制面请求加 JPEG 回传，不是持续 `/ws/camera` 二进制媒体流。
3. `find_object` 当前是盲人业务工程中的真实场景能力，相关实现优先看 [../capabilities/find_object](../capabilities/find_object) 和 [../capabilities/find_object/phone/ios](../capabilities/find_object/phone/ios)。
4. [../../openaiglass-sdk/docs/experimental](../../openaiglass-sdk/docs/experimental) 下内容是方案调研或 demo，不代表当前主链路已经全部采用。
5. [../../origin-project](../../origin-project) 是旧项目参考，不是当前运行主工程。

## 跨设备联调顺序

1. 启动服务端，确认 `/api/health` 和 `/api/runtime/devices` 正常。
2. 启动 iOS 手机端，确认手机注册、心跳、局域网地址和 camera sink 地址进入运行态。
3. 启动 ESP32 眼镜端，确认眼镜注册、心跳、语音会话打开和音频上行连接。
4. 触发语音对话，观察服务端 `voice_runtime`、`agent_core`、TTS、`/stream.wav` 日志。
5. 触发 `capture_photo` 或通过业务示例入口触发 `start_find_object`，观察服务端任务事件、眼镜视频/抓拍控制消息、手机端视频帧与检测结果。

更细的真机前检查和日志观察点见 [../../openaiglass-sdk/docs/sdk-design/SDK真机联调前检查与联调步骤.md](../../openaiglass-sdk/docs/sdk-design/SDK真机联调前检查与联调步骤.md)。
