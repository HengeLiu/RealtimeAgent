# 当前实现状态

本文按当前代码整理，目的是让开发人员先知道真实运行面，再阅读历史迭代记录或能力实施说明。更新时间：2026-04-29。

## 总体结论

当前仓库已经拆成两条主线：

1. [../../openaiglass-sdk](../../openaiglass-sdk)：三端 SDK 框架，承载服务端运行时、协议、公共模型、Tool/Task/Skill、设备级回放工具和 SDK 文档。
2. [..](..)：盲人 AI 眼镜真实场景工程，承载 `find_object`、`traffic_light`、`navigation`、`timer` 等业务能力、iOS 手机端、ESP32 眼镜端和设备级回放资产。

服务端真实实现已经迁入 SDK：

1. [../../openaiglass-sdk/server-python/app/main.py](../../openaiglass-sdk/server-python/app/main.py)：SDK 内真实服务端入口，承载 HTTP、控制 WebSocket、音频 WebSocket 和运行时装配。
2. [../host/server/main.py](../host/server/main.py)：盲人业务服务端宿主入口，通过 `OpenAIGlassesSDK` 注册 `find_object`、`traffic_light`、`navigation`、`timer` 等业务能力。

## 需要注意的真实边界

1. 普通对话路径已经具备模型文本增量到流式 TTS 的主链路，并在 sdk-v45 到 sdk-v47 增加了 TTS 首包诊断和预热；真实首听延迟仍会受模型首 token、TTS 服务首包、端侧播放和网络影响。
2. 单次抓拍当前是控制面请求加 JPEG 回传，不是持续 `/ws/camera` 二进制媒体流。
3. `find_object` 和 `traffic_light` 当前是手机视觉类样板能力，相关实现优先看 [../capabilities/find_object](../capabilities/find_object)、[../capabilities/traffic_light](../capabilities/traffic_light) 和各自 `phone/ios` 目录；业务侧不再通过宿主代码补 SDK 视频链路 adapter。
4. `navigation` 当前已完成路线准备、POI 候选、地理编码和红绿灯视觉事件最小策略，AMap adapter 仍是业务侧 mock，不代表已经接入真实地图服务或复杂最后 10 米策略。
5. `timer` 当前不在业务侧创建后台线程；如果产品要求服务端自然到点提醒，需要继续确认 SDK 通用定时事件调度能力。
6. [../../openaiglass-sdk/docs/experimental](../../openaiglass-sdk/docs/experimental) 下内容是方案调研或 demo，不代表当前主链路已经全部采用。
7. [../../origin-project](../../origin-project) 是旧项目参考，不是当前运行主工程。

## 推荐开发验证命令

SDK 测试：

```bash
PYTHONPATH=openaiglass-sdk/server-python:openaiglass-for-blind:. uv run python -m pytest openaiglass-sdk/tests -q
uv run openaiglass.sdk.package-check
```

盲人业务工程：

```bash
uv run openaiglass.server.run --app-module host.server.main --app-root openaiglass-for-blind
uv run openaiglass.sdk.preflight --report openaiglass-for-blind/logs/sdk-preflight-current.json
uv run openaiglass.sdk.live-check --report openaiglass-for-blind/logs/sdk-live-check-current.json
```

真实音频样例回归：

```bash
uv run openaiglass.sdk.audio-samples
```

## 跨设备联调顺序

1. 启动服务端，确认 `/api/health` 和 `/api/runtime/devices` 正常。
2. 启动 iOS 手机端，确认手机注册、心跳、局域网地址和 camera sink 地址进入运行态。
3. 启动 ESP32 眼镜端，或通过 `openaiglass.glass.start --runtime playback --config ...` 启动 `glass-playback`，确认眼镜注册、心跳、语音会话打开和音频上行连接。
4. 触发语音对话，观察服务端 `voice_runtime`、`agent_core`、TTS、`/stream.wav` 日志。
5. 触发 `capture_photo` 或通过业务示例入口触发 `start_find_object`，观察服务端任务事件、眼镜视频/抓拍控制消息、手机端视频帧与检测结果。

更细的真机前检查和日志观察点见 [../../openaiglass-sdk/docs/sdk-design/SDK真机联调前检查与联调步骤.md](../../openaiglass-sdk/docs/sdk-design/SDK真机联调前检查与联调步骤.md)。
