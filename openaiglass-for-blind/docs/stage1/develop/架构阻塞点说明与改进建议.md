# 架构阻塞点说明与改进建议

更新时间：2026-05-01

本文只记录当前仍会影响业务能力开发的 SDK 边界问题。已经修复或已经被当前代码覆盖的旧阻塞点不再保留；历史原因可查 SDK `stage2/iteration-v*.md`。

## 1. 当前结论

当前业务侧仍有两个会影响真实业务闭环的 SDK 边界问题：

1. SDK 目前提供的是“业务注册一个 `BaseMcpAdapter`”的 adapter 扩展面，还没有公开的外部 MCP client 能力，业务侧不能直接配置并连接官方 AMap MCP Server 的 stdio/SSE 进程。当前导航能力只能在业务 adapter 内调用高德 Web 服务，并通过 `context.mcp(...)` 暴露为 SDK MCP 方法。
2. SDK 自定义 Task 没有公开的通用定时调度接口，也没有公开字段让业务 Task 声明“终态事件必须先回流 Agent 决策，再通知用户”。当前 `timer_task` 可用业务侧轻量倒计时验证自然到点和通知，但还不能严格实现“到点主动通知 agent，agent 再主动通知用户”。

## 2. 当前业务侧不再处理的内容

以下内容不应由 `openaiglass-for-blind` 业务侧补丁处理：

1. 不手写 `/ws/control`、`/ws/camera`、`/ws_audio` 或 `voice.realtime.*` 协议。
2. 不自行维护设备绑定表、在线表或视频链路状态机。
3. 不在业务宿主中直接调用 SDK 私有方法或 debug 方法来补齐系统任务装配。
4. 不在能力目录保留 `scenario.py` 或组件级 `ScenarioRunner`。
5. 不把 Python phone 代码作为真实 iPhone 能力入口；Python phone 代码只服务 mock、回放和契约验证。

## 3. 后续观察风险

这些不是当前硬阻塞，但进入真实产品能力后需要继续观察：

1. 真实 AMap adapter 接入后，SDK MCP 错误包装是否足以表达配额、鉴权、超时、候选 POI 歧义和路线不可达。
2. `navigation_task` 进入更复杂手机视觉协同时，通知去重、抢播策略和多任务资源仲裁是否需要更明确的 SDK 公共能力。
3. `timer_task` 的业务侧倒计时不具备进程重启恢复、租约和多实例防重能力，生产化应由 SDK 通用任务调度承载。
4. 全双工实时语音真机验收时，端侧 AEC/VAD 和 `voice.realtime.user_interrupt` 的可观测字段是否足够排障。
5. 真实 iPhone 视觉插件需要继续验证长期运行时的帧率、温控、后台切换和权限恢复行为。
