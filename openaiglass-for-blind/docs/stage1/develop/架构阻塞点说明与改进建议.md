# 架构阻塞点说明与改进建议

更新时间：2026-04-27

本文只记录当前最新一轮业务开发遇到的未疏通阻塞点。旧阻塞点已经清理，避免 SDK 团队继续追踪已解决问题。

## 1. 当前结论：本轮没有新的 SDK 硬阻塞

本轮基于 `sdk-v3` 完成了 `navigation` 导航准备与任务最小闭环：

1. 业务侧在 `capabilities/navigation` 中实现 `PrepareNavigationTool`、`NavigationTask` 和 `MockAmapMcpAdapter`。
2. 业务 Tool 通过 `context.mcp("amap.route_plan", ...)` 调用 SDK 统一 MCP 入口。
3. MCP adapter 通过宿主入口 `sdk.register_mcp_adapter(...)` 注册。
4. 场景回放可验证 MCP trace、任务创建、任务状态和通知。

本轮没有修改 `openaiglass-sdk`，没有直接拼接 WebSocket、设备绑定表、`McpGateway` 或 `AgentToolContext`，符合当前 SDK 业务扩展边界。

## 2. 已清理的旧阻塞点

### 2.1 业务 Tool 缺少 MCP 调用入口

已由 `sdk-v3` 疏通。

当前代码证据：

1. `openaiglass-sdk/server-python/openaiglasses/runtime/device_group.py` 中 `DeviceGroupContext.mcp(...)` 已存在。
2. `OpenAIGlassesSDK.register_mcp_adapter(...)` 可注册业务项目自己的 MCP adapter。
3. `DeviceGroupRuntime.list_mcp_traces()` 可在离线回放中断言 MCP 调用轨迹。

本轮 `navigation_prepare_basic` 场景已验证 `amap.route_plan` trace 状态为 `succeeded`。

### 2.2 SDK 预检边界扫描命中 SDK 测试内业务关键词

已由当前 SDK 预检规则疏通。

本轮执行：

```bash
uv run python scripts/run_sdk_preflight.py --report logs/sdk-preflight-current.json
```

结果：

1. `check_count == 9`
2. `passed_count == 9`
3. `failed_count == 0`
4. `sdk_boundary.ok == true`
5. `sdk_boundary.details.violation_count == 0`

## 3. 后续观察风险

以下不是当前阻塞点，不需要 SDK 团队立即改框架；只是后续从 mock 导航进入真实执行期时需要继续观察：

1. 真实 AMap adapter 接入后，SDK 现有 MCP 错误包装是否足以表达配额、鉴权、超时、候选 POI 歧义和路线不可达。
2. `navigation_task` 进入手机视觉协同后，事件优先级、通知去重和抢播策略是否需要 SDK 提供更明确的通用能力。
3. 当前场景回放器的通用 `supported_timeline_event_types` 文案没有展示业务自定义事件类型，例如 `navigation.progress`，但不影响回放执行。
