# 架构阻塞点说明与改进建议

更新时间：2026-04-29

本文只记录当前仍会影响业务能力开发的 SDK 边界问题。已经修复或已经被当前代码覆盖的旧阻塞点不再保留；历史原因可查 SDK `stage2/iteration-v*.md`。

## 1. 当前结论

当前业务侧不再有必须由业务目录补丁绕过的 SDK 硬阻塞：

1. `DeviceGroupRuntime` 的视频链路启动、停止适配器已经由 SDK `ControlRuntime` 标准绑定，`openaiglass.sdk.preflight` 会检查该项。
2. `glass-playback` 已支持 `voice.session.open` 和 `voice.realtime.session.open` 两种会话打开事件，并会把服务端下发的 `session_id` 用于后续音频段。
3. `BaseMcpAdapter`、`McpMethodSpec` 和 `CapabilityResult` 已从 `openaiglasses` 公开入口导出，业务 MCP adapter 不需要再直接依赖 `agent_core` 内部路径。
4. 业务能力仍应只通过 `BaseTool`、`BaseTask`、`BasePhoneTask`、`BasePhoneProcessor`、`TaskContext`、`DeviceGroupContext` 和 `context.mcp(...)` 表达逻辑。

## 2. 当前业务侧不再处理的内容

以下内容不再由 `openaiglass-for-blind` 业务侧补丁处理：

1. 不手写 `/ws/control`、`/ws/camera`、`/ws_audio` 或 `voice.realtime.*` 协议。
2. 不自行维护设备绑定表、在线表或视频链路状态机。
3. 不在业务宿主中直接调用 SDK debug 方法来补齐系统任务装配。
4. 不在能力目录保留 `scenario.py` 或组件级 `ScenarioRunner`。
5. 不把 Python phone 代码作为真实 iPhone 能力入口；Python phone 代码只服务 mock、回放和契约验证。

## 3. 后续观察风险

这些不是当前硬阻塞，但进入真实产品能力后需要继续观察：

1. 真实 AMap adapter 接入后，SDK MCP 错误包装是否足以表达配额、鉴权、超时、候选 POI 歧义和路线不可达。
2. `navigation_task` 进入更复杂手机视觉协同时，通知去重、抢播策略和多任务资源仲裁是否需要更明确的 SDK 公共能力。
3. `timer_task` 如果要求真实自然到点，SDK 是否需要提供通用定时事件调度能力。当前业务侧不私建线程。
4. 全双工实时语音真机验收时，端侧 AEC/VAD 和 `voice.realtime.user_interrupt` 的可观测字段是否足够排障。
5. 真实 iPhone 视觉插件需要继续验证长期运行时的帧率、温控、后台切换和权限恢复行为。
