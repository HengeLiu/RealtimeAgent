# 眼镜启动后 WiFi 连接方案（简化版）

## 1. 方案目标

眼镜上电后需要尽快连上可用网络，并在网络恢复后自动回到在线状态。  
本方案重点明确两件事：

- 两个 WiFi 的优先级选择规则。
- 连接失败后的持续重试方式。

## 2. 两个 WiFi 的优先级规则

设备预置两个可连接网络，按固定优先级选择：

1. 第一优先级：家庭/办公主网络。
2. 第二优先级：手机热点兜底网络。

选择原则：

- 每次尝试连接时，先检查第一优先级网络是否可用。
- 第一优先级可用就直接连接，不再尝试第二优先级。
- 只有第一优先级不可用时，才切换到第二优先级。
- 当两个网络都不可用时，本轮不连接，进入等待后重试。

该规则确保设备在主网络可用时始终优先回到主网络，不长期停留在热点网络。

## 3. 重试连接方式

为避免“频繁扫网”和“长时间卡死”，采用“连接超时 + 间隔重试”的循环机制：

1. 发起连接后，给出单次连接等待时长。
2. 若在等待时长内成功，进入在线状态。
3. 若超时未成功，判定本次失败并结束本轮尝试。
4. 等待一个固定重试间隔后，重新开始下一轮网络选择与连接。
5. 设备持续执行该循环，直到连上任一可用网络。

这一机制的效果是：

- 不会因为一次失败就停在离线状态。
- 不会因为过度重试导致系统资源被占满。
- 网络恢复后可以自动回连，无需人工干预。

## 4. 与启动和服务注册的关系

WiFi 连接是后续服务注册的前置条件。  
只有先连上网络，设备才会继续建立服务通道并完成注册；若网络中断，服务通道会随之断开，等待 WiFi 恢复后自动重建。

## 5. 联调建议

联调时优先验证以下结果，而不是关注底层实现细节：

1. 主网络可用时，设备是否总是优先连接主网络。
2. 主网络不可用时，设备是否自动切到热点网络。
3. 两个网络都不可用时，设备是否按固定节奏持续重试。
4. 网络恢复后，设备是否能自动恢复在线并继续注册流程。
