# 全双工实时语音对话验收方案

更新时间：2026-04-28

## 1. 验收目标

全双工实时语音专项的验收目标不是只证明“能听到声音”，而是证明 SDK 已经把实时收音、模型输出、播放仲裁、用户打断、降级和回放测试变成稳定框架能力。

## 2. 文档验收

通过标准：

1. 有专项计划、架构设计、开发方案和验收方案。
2. 文档明确半双工与全双工的边界。
3. 文档明确 SDK 与业务代码边界。
4. 文档明确端侧 AEC/VAD 与服务端运行时的职责划分。
5. 文档包含 PlantUML 时序图或状态图。

## 3. 协议验收

通过标准：

1. `voice.realtime.session.open/opened/closed` 可完整表达会话生命周期。
2. `voice.realtime.input.started/delta/committed` 可表达用户输入流。
3. `voice.realtime.user_interrupt` 可表达用户插话，并携带打断原因和置信度。
4. `voice.realtime.output.delta/completed` 可表达模型下行输出流。
5. 半双工旧协议保持兼容。

## 4. 运行时验收

通过标准：

1. `RealtimeVoiceRuntime` 能维护明确状态机。
2. 乱序事件、重复关闭、迟到输出分片都有结构化处理。
3. 用户打断会进入 `PlaybackArbiter`，而不是直接操作播放器。
4. 运行态快照包含会话状态、输入流、输出流、最近事件、最近打断和延迟指标。
5. 实时模型不可用时可以降级到半双工链路。

## 5. 播放仲裁验收

必须覆盖以下场景：

| 场景 | 预期 |
| --- | --- |
| 普通 Agent 回复播放中用户插话 | 当前输出被取消，设备收到中断指令，用户输入继续处理。 |
| 任务通知播放中用户插话 | 按通知优先级和恢复策略决定停止、排队或保留。 |
| critical 视觉告警播放中用户插话 | 告警不被普通插话吞掉，用户输入在告警后继续处理。 |
| 用户连续插话 | 旧输出流不会复活，新输入流按顺序提交。 |

## 6. 回放测试验收

必须新增或扩展回放样例：

1. `full_duplex_user_barge_in`：播放中有效用户语音触发打断。
2. `full_duplex_echo_rejected`：播放音频被采回上行但不触发打断。
3. `full_duplex_model_first_delta_timeout`：模型首包延迟超过阈值时断言失败。
4. `full_duplex_late_output_after_interrupt`：用户打断后迟到输出被丢弃。
5. `full_duplex_degrade_to_half_duplex`：设备能力不足时结构化降级。

断言至少包括：

1. 事件顺序。
2. 状态迁移。
3. 打断决策原因。
4. 延迟阈值。
5. 最终快照字段。

## 7. 真机联调验收

启动顺序：

1. 启动服务端，开启 DEBUG 日志和实时语音运行态快照。
2. 启动手机侧 SDK 或中继客户端，确认账号、设备绑定和远程配置加载完成。
3. 启动眼镜端，确认麦克风、喇叭、AEC/VAD 能力上报。
4. 打开 `full_duplex_realtime` 会话。
5. 先做普通问答，再在播放期间插话，再做视觉告警抢播冲突测试。

观察点：

1. 端侧日志：AEC 状态、VAD 触发、打断置信度、上行帧序号。
2. 手机侧日志：音频路由、中继延迟、资源占用。
3. 服务端日志：状态迁移、模型首包、播放仲裁、打断决策。
4. 回放产物：事件时间线、媒体帧索引、最终快照。

通过标准：

1. 播放期间用户插话的体感延迟可接受，并能在日志中定位。
2. 普通喇叭回声不会频繁误触发打断。
3. 视觉 critical 告警不会被普通用户插话吞掉。
4. 会话关闭后没有残留播放流或输入流。

## 8. 回归验收命令

基础回归：

```bash
PYTHONPATH=openaiglass-sdk/server-python:openaiglass-for-blind uv run --with pytest python -m pytest openaiglass-sdk/tests/unit -q
python -m compileall -q openaiglass-sdk/server-python
git diff --check
```

新增专项回放测试后追加：

```bash
PYTHONPATH=openaiglass-sdk/server-python:openaiglass-for-blind uv run --with pytest python -m pytest openaiglass-sdk/tests/replay -q
```

真机联调完成后，需要把关键日志和回放产物路径写入对应迭代记录。
