# 真实音频样例批量回归说明

## 1. 目标

本说明用于通过仓库内真实音频样例目录 [audio-sample](/Users/elio/dev/llm-project/OpenAIglassesDemo_2/server/test/data/audio-sample) 对当前服务端做批量回归。

适用场景：

1. 验证真实语音样例在当前服务端是否仍能完成主链路。
2. 观察不同样例对应的回复文本和回复音频是否异常。
3. 快速筛选“哪条样例开始回归失败了”。

## 2. 前置条件

先确保服务端已经启动，并能通过以下配置接受模拟眼镜连接：

```bash
export DASHSCOPE_API_KEY="<your-api-key>"
export DEVICE_TOKEN_MAP="glass-001=pair-demo-token"
export LOG_FILE="logs/server.log"
PYTHONPATH=openaiglass-sdk/server-python python -m app.main --host 0.0.0.0 --port 8765
```

## 3. 执行命令

### 3.1 跑全部真实样例

```bash
bash script/run_audio_samples.sh \
  --host 127.0.0.1 \
  --port 8765
```

### 3.2 只跑单条样例

```bash
bash script/run_audio_samples.sh \
  --host 127.0.0.1 \
  --port 8765 \
  --sample "你是谁呀"
```

### 3.3 指定多条样例

```bash
bash script/run_audio_samples.sh \
  --host 127.0.0.1 \
  --port 8765 \
  --sample "帮我设置一个三分钟的计时器" \
  --sample "看一下我前面有什么"
```

### 3.4 自定义输出目录

```bash
bash script/run_audio_samples.sh \
  --host 127.0.0.1 \
  --port 8765 \
  --output-root runs/audio-sample-regression-20260418
```

## 4. 输出结果

脚本会在输出目录下生成：

1. `summary.json`
2. 每条样例自己的目录
3. 每条样例的 `reply.wav`
4. 每条样例的 `result.json`

`result.json` 当前还会额外带上：

1. `session_id`
2. `agent_session.messages`
3. `agent_session.capability_traces`
4. `agent_session.assets / artifacts / tasks`
5. `agent_session.model_request`

其中 `agent_session.messages` 现在会保留完整消息序列，首条会补上当前服务端使用的 `system_prompt`，后面再依次是本轮与历史的 `user / assistant` 消息。

其中 `agent_session.model_request` 是 agent-core 最终送给模型的一次请求视图，当前至少包含：

1. `model`
2. `instructions`
3. `messages`

终端还会打印：

1. 批量成功/失败总数
2. 每条样例的 `OK/FAIL`
3. 每条样例解析到的 `reply_text`

## 5. 建议观察点

建议重点看：

1. 哪条样例失败了
2. 失败样例的 `stderr`
3. 成功样例的 `reply_text`
4. `reply.wav` 是否能正常播放
5. `summary.json` 里的通过率
6. `result.json -> agent_session.capability_traces` 是否符合预期工具调用链路

## 6. 服务端 Debug 日志

当服务端使用 `LOG_LEVEL=DEBUG` 启动时，当前会输出以下能力链路日志：

1. `tool.call / tool.result / tool.failed`
2. `mcp.call / mcp.result / mcp.failed`

这些日志会带 `session_id / device_id / turn_id`，可以和 `result.json` 里的 `session_id` 与 `agent_session.capability_traces` 对照排查。

如果同时设置了 `LOG_FILE`，同样的结构化日志还会额外写入日志文件，便于批量样例回归后直接按文件筛查问题：

```bash
LOG_LEVEL=DEBUG LOG_FILE=logs/server.log PYTHONPATH=openaiglass-sdk/server-python python -m app.main --host 0.0.0.0 --port 8765
```

## 7. 当前限制

1. 该脚本当前复用 `simple_glass_audio_client.py`，所以前提仍是服务端可访问。
2. 批量结果依赖服务端调试接口 `/api/agent/session`，若本轮会话尚未落盘完成，可能拿不到快照。
3. 若服务端切到了新的设备 ID 或 pair token，需要同步修改命令参数。
