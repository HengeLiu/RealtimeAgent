更新时间：2026-05-01

## 0. 当前实施进度

状态：第二轮代码已落地。除自由插话外，第一批基础设施已完成。

已完成：

1. `omni_realtime` 默认链路不再由 `voice-runtime` 自建 instructions 和工具处理流程。
2. `voice-runtime` 在音频段完成后创建 `AgentTurn(source=voice_raw_audio)`，通过 `AgentFacade.handle_turn(...)` 进入 Agent-Core。
3. Agent-Core 新增原生音频回复入口，由 Agent-Core 构造系统提示词、记忆片段、工具 schema 和工具处理器，再把音频、图片、工具调用交给 Omni Realtime 适配器。
4. Omni Realtime 返回的文本转写和助手回复会回填到 `AgentTurnResult.meta`，并写入会话消息，用于日志、上下文和后续记忆。
5. 原生音频回复的音频分片通过回调进入现有 `/stream.wav` 播放流，保持当前下行播放方式。
6. 已补单元测试覆盖：
   - Omni 模式段开始时不再预推旧 Realtime 会话。
   - Agent-Core 原生音频入口可以拿到音频、系统提示词、工具 schema，并能执行工具。
   - AgentFacade 基础持久化仍可用。
7. 新增 `TurnEvent` / `TurnCoordinator`，每轮 `AgentFacade.handle_turn(...)` 会记录 `turn.started`、`input.assets.saved`、`text.final` / `turn.failed`、`turn.finished` 等事件，并把 `generation_id` 与事件快照写入 `AgentTurnResult.meta`。
8. 新增 `ModelCapability`、`ImageInputPolicy`、`AgentInputPlanner`，自动照片会被显式规划为直传图片或后置图片资产；当前默认 Omni 链路仍直传图片。
9. Runner 已按 `direct_image_asset_ids` 过滤图片输入，后置图片会保存为资产但不会被直接塞进模型输入。
10. 旧的 `voice-runtime` Omni helper 分支已删除，`omni_realtime` 直出路径只保留通过 Agent-Core 的实现。

暂未完成：

1. 自由插话仍不作为默认能力，本轮不重新启用端侧播放中 VAD 打断。
2. 视觉工具后置解读只完成资产规划和 runner 过滤，尚未新增可供模型调用的 `understand_current_image` 工具；当前默认产品链路仍使用 Omni 图片直传。

## 1. 文档定位

本文档是 [../../structure-design/统一多模态流式处理架构设计.md](../../structure-design/统一多模态流式处理架构设计.md) 的落地计划。

目标是在不破坏当前可用语音链路的前提下，逐步把音频、图片、文本、工具调用、TTS、Omni Realtime 和未来打断能力收敛到统一流式架构。

## 2. 当前基线

当前代码中需要重点处理的现状：

1. `VOICE_REPLY_MODE=omni_realtime` 时，`voice-runtime` 直接执行 Omni Realtime 语音直出。
2. `agent_tts` 分支进入 `AgentFacade.handle_turn(...)`，可以使用 Agent-Core 的上下文、记忆、工具和流式 TTS。
3. Agent-Core 内部已存在音频原生 Chat Completions 路径，可以把 `input_audio` 和 `image_url` 放进当前轮模型输入。
4. 自动抓拍图片当前由 `AgentFacade` 隐式消费并挂到当前 `AgentTurn`。
5. 播放仲裁、TTS 预热和 `/stream.wav` 已经可用，但还不是统一输出节点。

本计划的核心原则是先统一入口，再统一事件，再抽象节点。

目标：在开始重构前，明确当前行为并防止回归。

任务：

1. 为当前 `omni_realtime`、`agent_tts`、音频原生 Chat Completions 三条路径补齐调用链说明。
2. 固化日志字段：
   - `session_id`
   - `turn_id`
   - `segment_id`
   - `stream_id`
   - `reply_mode`
   - `input_modality`
   - `output_modality`
   - `model_name`
3. 回放测试覆盖：
   - 单轮语音问答。
   - 连续两轮语音问答。
   - 带自动照片的语音问答。
   - 工具调用。
   - TTS 播放完成。
4. 明确当前默认产品形态：
   - 真实眼镜保持半双工稳定链路。
   - 自由插话不作为默认能力。

验收：

1. `glass-playback` 连续音频回放稳定。
2. 服务端日志能打印文字版用户输入和助手回复。
3. 当前默认配置下不新增行为变化。

## 4. 阶段 1：让所有大模型决策进入 Agent-Core

目标：消除 `voice-runtime` 自建 Omni Agent 链路。

任务：

1. 在 Agent-Core 内新增或收敛 `RealtimeOmniModelAdapter`。
2. 将 `VoiceRuntime._build_omni_realtime_instructions(...)` 的职责迁移到 Agent-Core instructions 构造体系。
3. 将 `VoiceRuntime._build_omni_realtime_tools(...)` 和 tool handler 迁移到 Agent-Core 工具循环或统一工具适配层。
4. `VoiceRuntime` 只负责：
   - 音频段管理。
   - 自动抓拍触发。
   - 创建 `AgentTurn`。
   - 接收输出事件并交给播放。
5. `VOICE_REPLY_MODE=omni_realtime` 仍保留为配置，但它只选择 Agent-Core 的模型适配器，不再绕过 `AgentFacade.handle_turn(...)`。

验收：

1. `omni_realtime` 下断点能进入 Agent-Core instructions 构造。
2. `omni_realtime` 下 memory、skill、tool 都按 Agent-Core 统一规则生效。
3. 文字交互日志从 Agent-Core 统一输出。
4. 原有 Omni Realtime 音频直出能力仍能播放。

## 5. 阶段 2：引入基础 TurnEvent 和 TurnCoordinator

目标：先建立流式事件骨架，但不大规模改写所有节点。

当前状态：已完成基础落地。`TurnEvent` 和 `TurnCoordinator` 位于 `agent_core.streaming`，`AgentFacade` 已在每轮处理时分配 `generation_id` 并记录事件快照。暂未把所有音频分片、模型分片和播放分片都改造成事件流。

任务：

1. 定义 `TurnEvent` 基类和核心字段：
   - `session_id`
   - `turn_id`
   - `generation_id`
   - `stream_id`
   - `causation_id`
   - `created_at_ms`
2. 定义第一批事件：
   - `TurnStarted`
   - `AudioChunk`
   - `AudioEnded`
   - `ImageAssetReady`
   - `TextFinal`
   - `ModelTextDelta`
   - `ModelAudioChunk`
   - `PlaybackAudioChunk`
   - `TurnFinished`
   - `TurnFailed`
3. 引入 `TurnCoordinator`：
   - 管理当前 active turn。
   - 分配 `generation_id`。
   - 过滤旧 generation 输出。
   - 记录 turn 生命周期。
4. 第一阶段可以使用适配层把现有同步函数包装成事件输入输出，不要求所有节点立刻 async 化。

验收：

1. 每轮语音都有稳定 `turn_id`。
2. 每段输出都有 `generation_id`。
3. 日志可以按 turn 聚合完整输入、模型、工具、播放。

## 6. 阶段 3：图片处理策略层

目标：把图片直传和图片工具后置解读从实现细节升级为显式策略。

当前状态：已完成策略层和直传过滤。`agent_core.modality` 提供 `ModelCapability`、`ImageInputPolicy` 和 `AgentInputPlanner`；自动照片会记录 `direct_image_asset_ids` / `deferred_image_asset_ids`。视觉工具后置解读暂不落地，避免在当前阶段引入新的模型链路和产品行为。

任务：

1. 新增 `ModelCapability` 配置结构：
   - `supports_text_input`
   - `supports_audio_input`
   - `supports_image_input`
   - `supports_text_output`
   - `supports_audio_output`
   - `supports_streaming`
   - `supports_tool_calling`
2. 新增 `ImageInputPolicy`：
   - `direct_when_supported`
   - `tool_when_needed`
   - `disabled`
3. 新增 `ModalityRouter` 或 `AgentInputPlanner`。
4. 将自动照片消费从隐式逻辑调整为：
   - 图片先成为 `ImageAssetReady`。
   - 策略层决定放入 `direct_model_inputs` 或 `deferred_assets`。
5. 新增视觉工具：
   - `understand_current_image(question: str = "")`
   - 工具内部读取当前 turn 的 deferred image assets。
   - 工具可调用专用视觉模型返回文本摘要。

验收：

1. 支持视觉的模型可以直接收到图片。
2. 不支持视觉的模型可以通过工具理解图片。
3. 用户未问图片时，提示词或策略能避免无意义图片描述。
4. 图片 asset 只归属当前 turn，不会串到下一轮。

## 7. 阶段 4：输入模态节点化

目标：把 ASR、音频直传、图片直传做成可组合输入节点。

任务：

1. 定义 `StreamNode.process(...)` 接口。
2. 实现第一批输入节点：
   - `AsrNode`
   - `AudioPassthroughNode`
   - `ImagePassthroughNode`
   - `BatchBarrierNode`
3. `AsrNode` 先包装现有实时 ASR 和批量 ASR。
4. `AudioPassthroughNode` 先包装当前 WAV/PCM asset 传递逻辑。
5. `ImagePassthroughNode` 只输出图片资产事件，不处理图片策略。

验收：

1. `agent_tts` 可以表达为 `audio -> ASR -> AgentCore -> TTS`。
2. `omni_realtime` 可以表达为 `audio -> passthrough -> AgentCore`。
3. 单元测试能单独测试 ASR 节点和图片节点。

## 8. 阶段 5：输出模态节点化

目标：统一 TTS 和模型音频直出。

任务：

1. 实现输出节点：
   - `TtsNode`
   - `AudioOutputPassthroughNode`
   - `TextLogNode`
   - `PlaybackSinkNode`
2. `TtsNode` 包装现有 CosyVoice 流式 TTS 和预热逻辑。
3. `AudioOutputPassthroughNode` 包装 Omni Realtime 音频 delta。
4. `PlaybackSinkNode` 包装现有播放流、播放仲裁和 HTTP 下行。
5. 输出侧强制要求：
   - 有文本输出就进入文字日志。
   - 有音频输出就进入播放 sink。
   - 没有文本 side channel 的音频模型需要 transcript 兜底。

验收：

1. TTS 音频和模型音频直出共享同一播放仲裁。
2. 播放日志字段统一。
3. 每轮都有 `AssistantTextFinal` 或结构化空文本原因。

## 9. 阶段 6：工具副作用与打断基础

目标：为未来打断做基础设施，不默认开放自由插话。

当前状态：原生音频直出链路已先落地 `manage_memory` 后台化。它属于低优先级副作用工具，不影响当前回复内容，可先让模型继续生成首段音频，再由后台线程完成真实记忆写入。`memory_search`、导航、计时器、找物、红绿灯等会影响当前回答或创建用户可感知任务的工具仍保持同步执行。

任务：

1. 工具 spec 增加副作用策略：
   - `ephemeral`
   - `committed`
   - `confirm_required`
2. 增加控制事件：
   - `CancelTurn`
   - `BargeInStarted`
   - `OutputDiscarded`
   - `NodeCancelled`
3. 所有输出节点检查 `generation_id`。
4. 播放层拒绝旧 generation 音频。
5. 模型、ASR、TTS、播放流提供 cancel 接口。
6. 不能真实取消的外部调用必须允许下游丢弃结果。

验收：

1. 手动打断后旧回复不再继续播放。
2. 被打断 turn 的工具副作用有明确记录。
3. 打断后新 turn 可以正常进入 Agent-Core。
4. 回放测试可复现 cancel 后旧音频被丢弃。

## 10. 阶段 7：产品化打断能力

目标：按风险分级开放打断。

建议顺序：

1. 保持半双工默认。
2. 支持手动打断。
3. 支持唤醒词打断。
4. 支持自由插话灰度。

自由插话开放条件：

1. 端侧 AEC/VAD 可稳定区分播放声和用户声。
2. 误打断率可通过回放和真机测试量化。
3. 服务端 generation gating 已稳定。
4. Omni 或 ASR 事件不会因旧会话关闭产生大量错误噪声。

验收：

1. 播放中无用户说话时不应自循环打断。
2. 用户明确打断时，旧播放在可接受延迟内停止。
3. 新输入不会混入旧回复尾音。

## 11. 建议优先级

最高优先级：

1. 所有大模型决策进入 Agent-Core。
2. 保证文字版交互日志。
3. 图片策略显式化。

中优先级：

1. TurnEvent 基础模型。
2. 输入输出节点包装。
3. generation gating。

低优先级：

1. 完整自动模型能力探测。
2. 自由插话默认开启。
3. 所有节点完全 async 化。

## 12. 迁移注意事项

1. 不要一次性删除当前稳定的 `agent_tts` 或播放链路。
2. 不要让图片策略写死在 prompt 里。
3. 不要通过模型名字符串判断所有能力，短期可以配置优先，模型名推断只作为默认值。
4. 不要让 `voice-runtime` 再新增业务工具处理逻辑。
5. 不要把工具副作用当作可随意取消的流式输出。

## 13. 最终完成标准

完成后，系统应满足：

1. 语音输入、图片输入、文本输入都进入统一 `AgentTurn` 或 `TurnEvent`。
2. Agent-Core 是唯一模型决策入口。
3. 图片直传和视觉工具后置由策略层动态决定。
4. 文本输出、TTS 输出、模型音频直出都通过统一输出事件进入播放。
5. 每轮交互都有可读文字日志。
6. 每个输出片段都有 turn 和 generation 归属。
7. 手动打断具备端到端可验证能力。
