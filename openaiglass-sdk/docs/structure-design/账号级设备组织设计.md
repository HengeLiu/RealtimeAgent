# 账号级设备组织设计

版本：sdk-v16

## 目标

本轮把“多设备组织和账号级管理”收敛为 SDK 运行时能力，而不是业务能力。SDK 负责维护账号、设备、设备组、绑定关系、组织树、角色权限、审计事件和远程配置 Provider，让功能开发者只表达设备归属、绑定意图和必要的权限动作。

## 范围

sdk-v9 已实现：

1. `device.register` 可携带 `account_id` 和 `user_id`。
2. `DeviceGroupRuntime.register_device()` 支持账号字段。
3. `DeviceGroupRuntime.bind_devices()` 拒绝跨账号绑定。
4. `runtime.device_groups.accounts[]` 输出账号级设备、设备组和绑定快照。
5. 只有一方声明账号时，绑定后 SDK 会把同组设备归入该账号，兼容旧设备。

sdk-v16 新增：

1. `AccountGovernanceRuntime`：账号治理运行时。
2. `OrganizationNode`：组织树节点。
3. `RoleBinding` 和 `PermissionPolicy`：最小 RBAC 权限模型。
4. `AuditEvent`、`MemoryAuditSink`、`FileAuditSink`：审计事件输出。
5. `MemoryConfigProvider`、`FileConfigProvider`：远程配置 Provider 第一版。
6. `DeviceGroupContext.get_config(...)` 和 `require_permission(...)`：业务上下文中的配置读取和权限检查入口。

仍不在本轮范围：

1. 商业管理后台 UI。
2. 外部用户中心、SSO、OAuth 或企业身份系统。
3. 云端配置服务和多实例配置推送。
4. 多实例服务之间的设备状态同步。

## 注册消息扩展

```json
{
  "name": "device.register",
  "payload": {
    "device_id": "glass-001",
    "device_type": "glass",
    "account_id": "acct-demo",
    "user_id": "user-demo",
    "auth": {
      "mode": "pair_token",
      "pair_token": "pair-demo-token"
    }
  }
}
```

`account_id` 是设备组织边界。两个设备都声明账号时，账号必须一致才能绑定。

## 运行态快照

```json
{
  "device_groups": {
    "accounts": [
      {
        "account_id": "acct-demo",
        "user_id": "user-demo",
        "device_ids": ["glass-001", "phone-001"],
        "group_ids": ["group_xxx"],
        "online_device_count": 2,
        "bindings": [
          {
            "group_id": "group_xxx",
            "glass_device_id": "glass-001",
            "phone_device_id": "phone-001"
          }
        ]
      }
    ]
  }
}
```

## 业务开发边界

功能代码不要自行维护全局设备表。需要当前任务相关设备时，使用 `DeviceGroupContext.require_glass()`、`require_phone()`、`query_devices()`；需要账号级观察时，读取运行态快照或等待 SDK 后续提供更高层查询 API。

## sdk-v16：权限、组织树、审计和远程配置中心

sdk-v16 已把账号组织能力从“运行态归属”升级为“可授权、可审计、可配置”的 SDK 基础设施。

### 核心对象

| 对象 | 职责 |
| --- | --- |
| `AccountGovernanceRuntime` | 管理组织节点、角色绑定、权限决策、审计事件和配置 Provider。 |
| `OrganizationNode` | 描述组织树节点，支持父子关系和路径查询。 |
| `RoleBinding` | 描述用户、设备或服务账号在某个组织节点上的角色。 |
| `PermissionPolicy` | 统一判断某次注册、绑定、任务或工具调用是否允许。 |
| `AuditSink` | 输出审计事件，第一版支持内存和文件。 |
| `ConfigProvider` | 读取 SDK 策略配置，第一版支持内存和文件，预留 HTTP Provider。 |

### 权限检查点

SDK 提供统一权限检查入口，后续可逐步接入更多运行时检查点：

1. 设备注册时会记录审计事件，并为 `user_id` 自动绑定账号 owner 角色。
2. 设备绑定时继续拒绝跨账号绑定，并记录 allow/deny 审计事件。
3. `DeviceGroupContext.require_permission(...)` 可在 Task、Tool 或宿主入口做显式权限检查。
4. `DeviceGroupRuntime.authorize(...)` 可按账号或设备组作用域检查 `task.create`、`tool.invoke`、`config.read` 等动作。
5. 远程配置读取通过 `DeviceGroupContext.get_config(...)` 或 `DeviceGroupRuntime.get_config(...)` 统一进入 Provider。

### 审计事件

审计事件用于排查和追责，不替代业务日志：

```json
{
  "event_id": "audit_xxx",
  "account_id": "acct-demo",
  "org_id": "org-demo",
  "actor_id": "user-demo",
  "resource_type": "device_group",
  "resource_id": "group_xxx",
  "action": "task.create",
  "decision": "deny",
  "reason": "cross_org_access",
  "created_at_ms": 1710000000000
}
```

### 配置中心边界

第一版远程配置中心不是商业后台，也不依赖外部云服务。SDK 只提供 Provider 抽象和本地实现：

1. `MemoryConfigProvider` 用于单元测试和本地开发。
2. `FileConfigProvider` 用于单机部署和回放。
3. `HttpConfigProvider` 暂不实现，后续接真实配置服务时复用 `ConfigProvider` 接口。

配置项应先覆盖 SDK 策略，例如视觉资源预算、播放仲裁策略、任务持久化类型和默认权限策略，不承载业务算法参数。

配置文件格式示例：

```json
{
  "version": "local-v1",
  "values": {
    "global": {
      "sdk.playback.default_priority": "normal"
    },
    "account:acct-demo": {
      "sdk.vision.max_concurrent_tasks": 1
    },
    "device:glass-001": {
      "sdk.playback.default_priority": "high"
    }
  }
}
```

配置读取优先级：

1. `device:<device_id>`
2. `group:<group_id>`
3. `account:<account_id>`
4. `global`
