# 任务持久化生产化设计

版本：sdk-v11

## 目标

本轮把 SDK 托管任务从“手动导出 JSON 快照”升级为单机生产化形态。目标是支持开发、回放、单机部署和服务重启恢复，同时不把数据库、多实例抢占和分布式锁提前做进 SDK。

## 已实现能力

1. `FileTaskPersistenceStore`：文件型任务存储。
2. `TaskRuntimeManager.enable_persistence(path, restore=True)`：启用自动持久化并可立即恢复。
3. 原子写入：使用临时文件写入后 `os.replace` 替换目标文件。
4. 自动保存：创建、取消、派发事件、恢复和清理都会触发保存。
5. 事件幂等：`dispatch_event` 支持 `event_id` 参数，也会识别 payload 中的 `event_id/idempotency_key`。
6. 终态清理：`prune_tasks(retain_terminal_ms=...)` 清理已完成、取消、失败或超时的旧任务。

## 文件格式

```json
{
  "version": "sdk-task-store-v1",
  "saved_at_ms": 1710000000000,
  "tasks": []
}
```

## 使用方式

```python
sdk.task_runtime.enable_persistence(
    "logs/sdk-task-store.json",
    restore=True,
)
```

端侧事件建议携带稳定事件编号：

```python
sdk.task_runtime.dispatch_event(
    task_id="task_xxx",
    event_name="phone.demo.done",
    payload={"event_id": "phone_evt_001", "ok": True},
    source="phone",
)
```

## 边界

sdk-v11 不是分布式任务平台，不解决：

1. 多实例抢占。
2. 数据库事务。
3. 分布式锁。
4. 跨进程事件消费。
5. 远程任务审计后台。

这些能力需要后续把 `FileTaskPersistenceStore` 替换为数据库存储，并为 `TaskRuntimeManager` 增加租约、事件游标和恢复协调。

## 下一轮：SQLite 任务持久化

下一轮把任务存储从文件快照升级到轻量数据库形态。第一版优先使用 Python 标准库 `sqlite3`，提供内存库和文件库两种模式：

1. `:memory:` 用于单元测试。
2. SQLite 文件库用于单机多进程、多 worker 的任务恢复和事件幂等。

SQLite 不解决跨机器分布式一致性；如果部署成多台服务器，需要后续替换为 PostgreSQL、MySQL 或其他外部数据库实现。

### 存储接口

`TaskRuntimeManager` 不应直接依赖 SQLite。建议保持可替换接口：

| 接口 | 职责 |
| --- | --- |
| `TaskPersistenceStore` | 任务快照、任务事件和租约的统一存储接口。 |
| `FileTaskPersistenceStore` | 兼容 sdk-v11 的文件型存储。 |
| `SQLiteTaskPersistenceStore` | 新增 SQLite 存储，支持事务、索引、幂等和租约。 |
| `InMemoryTaskPersistenceStore` | 测试用内存存储。 |

### 表结构草案

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `schema_migrations` | `version`、`applied_at_ms` | 记录数据库结构版本。 |
| `tasks` | `task_id`、`task_type`、`status`、`snapshot_json`、`updated_at_ms` | 保存任务当前快照。 |
| `task_events` | `task_id`、`event_id`、`event_name`、`payload_json`、`created_at_ms` | 保存事件日志，`event_id` 做幂等。 |
| `task_leases` | `task_id`、`owner_id`、`expires_at_ms`、`renewed_at_ms` | 控制单机多进程恢复和执行归属。 |

### 事务和 WAL

SQLite 文件库默认启用 WAL：

```sql
PRAGMA journal_mode=WAL;
PRAGMA synchronous=NORMAL;
```

任务状态推进和事件写入必须在同一事务内完成。重复事件通过唯一索引 `(task_id, event_id)` 去重，不能让业务 Task 自己处理重复消息。

### 恢复和租约

恢复流程建议：

1. 进程启动时扫描非终态任务。
2. 尝试获取或续租 `task_leases`。
3. 只有拿到租约的 manager 才恢复该任务。
4. 租约过期后其他 manager 可以接管。
5. 恢复失败要写入结构化错误和审计日志。

这套租约只保证单机 SQLite 文件内的多进程协调，不保证跨主机强一致。
