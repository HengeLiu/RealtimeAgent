# 手机视觉资源管理设计

更新时间：2026-04-28
对应版本：sdk-v14

## 1. 设计目标

手机视觉能力会持续消费眼镜视频帧，并可能同时运行多个任务。如果每个业务任务自己维护帧率、丢帧、过载和任务结果，就会把系统资源治理扩散到业务层。

本设计把第一版手机视觉资源管理收敛到 SDK 运行时：

1. SDK 负责根据任务参数限制帧处理频率。
2. SDK 负责记录被丢弃的帧和过载原因。
3. SDK 负责把资源事件写入手机任务快照，供回放测试和联调排查。
4. 业务任务只处理真正被 SDK 分发的帧，不直接管理帧队列和资源限制。

## 2. 当前实现范围

sdk-v6 首先在 Python `PhoneRuntime` 中落地资源策略，主要服务于 `phone-mock`、设备级回放测试和服务端侧手机任务模拟。sdk-v14 把同一类策略下沉到真 iOS 通用运行时。

当前已经支持：

1. `VisionTaskPolicy`
2. `vision_policy.min_frame_interval_ms`
3. `vision_policy.max_frames`
4. `vision_policy.priority` 字段透传和快照记录
5. `vision_policy.emit_overload_events`
6. `PhoneTaskSnapshot.frames_dropped`
7. `PhoneTaskSnapshot.resource_events`
8. `vision.task.overloaded` 结构化资源事件
9. iOS `VisionResourceCoordinator`
10. iOS 独占模型资源租约
11. iOS 高优先级任务抢占低优先级任务
12. iOS 低电量、后台和过热策略降频
13. iOS 资源事件本地日志与服务端任务事件回流

当前暂不支持：

1. 多模型加载、卸载和内存治理。
2. 真实视频帧队列的异步背压。
3. 基于真实设备电量和热状态的自动采样，当前先读取任务参数中的 `power_mode`。

这些内容将在后续 iOS 运行时资源管理迭代中继续补齐。

## 3. 任务参数

手机任务可以在启动参数中声明 `vision_policy`：

```json
{
  "stream_id": "stream_cam_001",
  "vision_policy": {
    "min_frame_interval_ms": 1000,
    "max_frames": 30,
    "priority": 10,
    "emit_overload_events": true
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `min_frame_interval_ms` | int | 同一个手机任务两次实际处理帧之间的最小间隔。 |
| `max_frames` | int | 单个任务最多允许处理的帧数，未设置或为 0 表示不限制。 |
| `priority` | int | 任务优先级，当前只记录和透传，后续用于资源仲裁。 |
| `emit_overload_events` | bool | 触发限流时是否记录 `vision.task.overloaded`。 |

为了兼容早期参数，SDK 也会读取顶层 `frame_interval_ms`、`min_frame_interval_ms`、`max_frames` 和 `priority`，但新代码应优先放入 `vision_policy`。

## 4. 资源事件

当 SDK 判断当前帧不能继续投递给任务时，会增加 `frames_dropped`，并在 `resource_events` 中记录事件：

```json
{
  "event_name": "vision.task.overloaded",
  "reason": "frame_rate_limited",
  "task_id": "phone_task_xxx",
  "task_type": "demo_phone_task",
  "stream_id": "stream_cam_001",
  "frame_ts_ms": 123456,
  "frames_processed": 1,
  "frames_dropped": 1,
  "min_frame_interval_ms": 1000,
  "max_frames": 30
}
```

当前 `reason` 取值：

| reason | 含义 |
| --- | --- |
| `frame_rate_limited` | 当前帧与上一帧实际处理时间间隔不足。 |
| `max_frames_reached` | 当前任务已经达到最大处理帧数。 |

资源事件只说明 SDK 因资源策略丢弃了帧，不代表业务能力失败。业务任务不应该把资源事件当成自己的业务结果。

## 5. SDK 运行时行为

`PhoneRuntime.process_frame(...)` 的处理顺序：

1. 按 `task_types` 过滤任务类型。
2. 按任务参数中的 `stream_id` 过滤视频流。
3. 对匹配任务执行 `VisionTaskPolicy` 检查。
4. 如果通过检查，调用业务任务 `on_frame(...)`。
5. 如果未通过检查，记录 `vision.task.overloaded`，不调用业务任务。

`process_frame(...)` 会返回所有匹配任务的快照。即使某个任务因资源策略丢帧，也会返回快照，让回放测试可以断言 `frames_dropped` 和 `resource_events`。

`process_task_frame(...)` 是指定任务的直接输入入口，也会执行同一套资源策略。

## 6. 开发者边界

业务手机任务应该遵守以下边界：

1. 不要自行维护全局帧队列。
2. 不要自行判断多个任务之间的资源优先级。
3. 不要把丢帧当成业务失败直接完成 Task。
4. 需要控制处理频率时，通过任务参数声明 `vision_policy`。
5. 需要观察资源问题时，看 `PhoneTaskSnapshot.resource_events` 和 DEBUG 日志，而不是在业务逻辑里临时打印。

真实 iOS 插件应声明 `vision_policy`，由 SDK iOS 通用运行时统一执行限流、抢占和功耗降级。业务插件只处理实际被投递的帧。

## 7. 验收口径

sdk-v6 当前自动化验收覆盖：

1. 固定帧间隔策略下，时间间隔不足的帧不会进入业务任务。
2. 达到最大处理帧数后，后续帧不会进入业务任务。
3. 被 SDK 丢弃的帧会记录 `vision.task.overloaded`。
4. 任务快照能看到 `frames_processed`、`frames_dropped`、`resource_events` 和 `vision_policy`。

sdk-v14 iOS 运行时资源管理验收覆盖：

1. 真机插件不需要自行实现帧率限流。
2. 达到最大帧数后，SDK 不再继续投递帧。
3. 低优先级任务可以被高优先级任务抢占。
4. 资源事件可以通过本地日志和服务端任务事件回流。

## 8. sdk-v14：真 iOS 运行时资源管理

本轮不再只停留在 Python `PhoneRuntime` 和 `phone-mock`，而是把资源管理下沉到真 iOS 运行时。目标是让 Swift 业务插件只声明资源需求，不自行维护模型实例、帧队列、抢占和功耗策略。

### 8.1 Swift 侧核心对象

| 对象 | 职责 |
| --- | --- |
| `VisionResourceCoordinator` | 统一接收手机任务启动、停止和视频帧输入，按策略分配资源。 |
| `VisionTaskLease` | 表示某个任务当前拿到的帧订阅、模型槽位和执行预算。 |
| `VisionModelPool` | 管理可复用模型实例，不绑定具体业务模型类型。 |
| `VisionPowerPolicy` | 根据电量、温度、后台状态和连续运行时长决定降频、暂停或拒绝新任务。 |
| `VisionPreemptionPolicy` | 在资源冲突时判断排队、拒绝、降级或抢占。 |

### 8.2 任务抢占语义

抢占只由 SDK 决策，业务插件不能直接停止其他插件。建议第一版规则：

1. `critical` 任务可以抢占 `background` 或 `normal` 任务。
2. `foreground` 任务优先于 `background` 任务。
3. 同优先级任务默认共享帧并按 `min_frame_interval_ms` 降频。
4. 被抢占任务收到 `vision.task.preempted`，并进入可恢复或终止状态。
5. 无法分配资源的新任务收到 `vision.resource.denied`，不能静默等待。

### 8.3 功耗治理语义

iOS 运行时需要把以下状态纳入资源策略：

1. 低电量：降低后台任务帧率，必要时拒绝新后台视觉任务。
2. 过热：暂停或降级高频任务，并上报 `vision.task.overloaded`。
3. App 进入后台：只保留允许后台运行的任务，其他任务降级或暂停。
4. 长时间连续推理：按配置触发冷却窗口，避免业务插件无限占用模型资源。

### 8.4 服务端回流事件

真机 iOS 运行时需要把资源决策通过任务事件回流服务端：

| 事件名 | 触发条件 |
| --- | --- |
| `vision.resource.lease_granted` | 任务获得帧订阅或模型资源。 |
| `vision.resource.denied` | 任务因资源不足、功耗策略或权限不足被拒绝。 |
| `vision.task.preempted` | 任务被更高优先级任务抢占。 |
| `vision.task.degraded` | 任务被降频或降级执行。 |
| `vision.task.overloaded` | 运行时发生丢帧、队列堆积或过热保护。 |

这些事件属于 SDK 系统事件，不是业务识别结果。
