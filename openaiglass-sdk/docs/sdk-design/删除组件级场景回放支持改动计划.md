# 删除组件级场景回放支持改动计划

## 1. 背景

SDK 测试策略已经收敛为设备级数据回放：功能开发人员通过独立的 `glass-playback` Python 虚拟眼镜设备，按真实设备方式连接真实服务端完成自测。

旧的组件级场景回放体系会绕过真实设备注册、设备绑定、语音会话和执行器协议，继续保留会让开发者误以为 SDK 同时支持两套测试模式。因此需要删除 `ScenarioRunner`、业务 `scenario.py`、`testdata/scenario` manifest 和相关文档入口。

删除后的正式口径是：

1. SDK 当前只支持 `glass-playback` 设备级数据回放。
2. 需要手机能力时使用真实 iOS phone。
3. 当前不支持断言检查。
4. 当前不支持批量测试。
5. 组件级测试如未来需要，由功能开发团队提出明确需求后重新设计。

## 2. 改动目标

1. 删除业务工程内组件级场景回放入口。
2. 删除能力目录中面向旧回放器的 `scenario.py` 处理器。
3. 删除或迁移旧 `testdata/scenario` manifest。
4. 删除预检脚本中 scenario 批量回放步骤。
5. 清理 README 和历史说明中对 `ScenarioRunner`、断言、批量回放的推荐。
6. 保留 SDK 公共契约测试、单元测试、真机联调检查和未来 `glass-playback` 工具测试。

| 路径 | 修改内容 |

## 4. 保留范围

以下能力不属于本次删除范围：

1. SDK 公共契约测试：`openaiglass-sdk/scripts/run_sdk_contract_tests.py`。
2. SDK 兼容性测试：`openaiglass-sdk/scripts/run_sdk_compatibility_tests.py`。
3. SDK 单元测试和集成测试：`openaiglass-sdk/tests`。
4. 真机联调检查：`run_sdk_live_check.py`、`sync_sdk_live_config.py`。
5. 服务端、真实 iOS phone、真实 ESP32 glass 的启动脚本。
6. `testdata/audio`、`testdata/image`、`testdata/video`、`testdata/sensor`、`testdata/text` 中仍可被 `glass-playback` 复用的资产。

## 5. 迁移原则

旧场景 manifest 中的内容按以下规则处理：

1. `inputs.audio` 或语音文本样例：转为 `trigger_audio` 所需音频资产；如果只有文本，后续需要补录或合成音频文件。
2. `inputs.video`、`inputs.frames`：迁移为 `camera_stream` 资产。
3. `inputs.heading`、位置、方向等数据：迁移为 `sensor` 资产。
4. `expected`：删除，不迁移到 `glass-playback` 配置。
5. `mocks`：默认删除；设备级回放应走真实服务端运行时，除非对应外部服务本身已有正式 adapter mock。
6. `phone_results`：不再作为组件回放输入；需要手机能力时使用真实 iOS phone。
7. `cancel` 时间线：不作为首期 `glass-playback` 自动脚本能力迁移；开发者先通过手动操作或真实控制路径验证。

## 6. 实施步骤

### 6.1 文档先行

1. 确认 SDK 指南第 10 节只描述设备级数据回放。
2. 确认 SDK 测试设计文档只保留 `glass-playback`。
3. 确认本删除计划列出所有旧入口。

### 6.2 清理预检与入口

1. 从 `run_sdk_preflight.py` 删除 `--skip-scenarios`。
2. 从 compileall 目标中删除 `scripts/run_sdk_scenario.py`。
3. 删除 `scenario_suite` 子命令执行。
4. 确认预检仍覆盖 compileall、entrypoints、boundary、package、contracts、compatibility、pytest、health。

### 6.3 删除旧回放代码

1. 删除 `scripts/run_sdk_scenario.py`。
2. 删除各能力目录下的 `scenario.py`。
3. 扫描 `from capabilities.*.scenario`、`ScenarioRunner`、`run_sdk_scenario` 引用并清零。

### 6.4 迁移测试资产

1. 删除 `testdata/scenario` 目录。
2. 保留可复用传感器资产，例如 `testdata/sensor/find_object_heading.json`。
3. 将未来 `glass-playback` 设备配置放入 `host/glass-playback/config`。
4. 补充或占位 `testdata/audio` 中的触发音频资产。

### 6.5 清理文档

1. 更新 `testdata/README.md`。
2. 更新业务能力 README。
3. 更新 `README.md` 和 `docs/当前实现状态.md`。
4. 扫描并清理公开文档中的“场景回放通过”“批量场景”“断言”表述。

### 6.6 验证

执行以下检查：

```bash
rg -n "ScenarioRunner|run_sdk_scenario|scenario.py|场景回放|批量回放|回放断言|--scenario|--scenario-dir" openaiglass-for-blind openaiglass-sdk
uv run python -m compileall openaiglass-sdk/server-python openaiglass-for-blind/host/server openaiglass-for-blind/host/phone/src openaiglass-for-blind/capabilities openaiglass-for-blind/scripts
uv run python openaiglass-sdk/scripts/run_sdk_contract_tests.py
uv run python openaiglass-sdk/scripts/run_sdk_compatibility_tests.py
uv run python -m pytest openaiglass-sdk/tests/contracts openaiglass-sdk/tests/unit/test_sdk_phase_two.py openaiglass-sdk/tests/unit/test_agent_core.py openaiglass-sdk/tests/unit/test_backend_task_core.py openaiglass-sdk/tests/integration/test_control_register_flow.py -q
```

`rg` 结果中允许历史实施记录保留“场景回放”字样，但 SDK 指南、README、当前状态和测试设计文档不得继续把它描述为当前支持能力。

## 7. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 删除旧回放后短期缺少自动业务回归 | 接受该状态；当前不支持断言和批量测试，业务开发者先用 `glass-playback` 输出人工判断。 |
| 旧 manifest 中部分素材仍有价值 | 只迁移原始资产，不迁移 `expected` 和 runner 专属字段。 |
| 文档中历史记录仍提到场景回放 | 历史实施记录可保留，但当前入口文档必须改口径。 |
| 功能开发人员误用组件级测试思路 | SDK 指南、测试设计和 README 明确 `glass-playback` 是独立设备。 |

## 8. 完成标准

本次删除完成后应满足：

1. 仓库中没有可执行的 `run_sdk_scenario.py`。
2. 能力目录不再包含 `scenario.py`。
3. 预检不再执行 scenario 批量回放。
4. `testdata/README.md` 不再推荐 `scenario` manifest。
5. 当前 SDK 文档只描述设备级数据回放。
6. 公开开发者指南不出现手机虚拟设备、断言检查和批量测试支持承诺。
7. 功能开发人员的测试路径收敛为：真实 server + 可选真实 iOS phone + 独立 `glass-playback` 虚拟眼镜设备。
