# 架构阻塞点说明与改进建议

更新时间：2026-05-02

本文只记录当前仍会影响业务能力开发的 SDK 边界问题。已经修复或已经被当前代码覆盖的旧阻塞点不再保留；历史原因可查 SDK `stage2/iteration-v*.md`。

## 1. 当前结论

当前业务侧仍有一个会影响真实业务闭环的 SDK 边界问题：

1. 2026-05-02 `find_object` 迁移真实手机端 YOLO 时发现，iOS `PhoneTaskCapabilityRuntime.processFrame(...)` 是同步帧处理接口，且当前 `CameraStreamStore.updateLatestFrame(...)` 在主线程更新 UI 状态后直接调用业务处理器。业务侧可以用 `frame_stride` 降低推理频率，但真实 CoreML YOLO 长时间运行仍需要 SDK 提供异步推理队列、背压、丢帧策略、温控降帧和任务取消时的推理中止语义，避免业务插件各自实现资源调度。

已由 `sdk-v84` 疏通并从当前阻塞移除：

1. 外部 MCP Server client。
2. SDK 自定义 Task 通用定时调度。
3. Task 终态事件回流 Agent 决策策略。
4. `DeviceGroupContext.submit_notification(...)` 到 `VoiceRuntime` 真实播报链路的绑定。

## 2. 当前业务侧不再处理的内容

以下内容不应由 `openaiglass-for-blind` 业务侧补丁处理：

1. 不手写 `/ws/control`、`/ws/camera`、`/ws_audio` 或 `voice.realtime.*` 协议。
2. 不自行维护设备绑定表、在线表或视频链路状态机。
3. 不在业务宿主中直接调用 SDK 私有方法或 debug 方法来补齐系统任务装配。
4. 不在能力目录保留 `scenario.py` 或组件级 `ScenarioRunner`。
5. 不把 Python phone 代码作为真实 iPhone 能力入口；Python phone 代码只服务 mock、回放和契约验证。

## 3. 后续观察风险

这些不是当前硬阻塞，但进入真实产品能力后需要继续观察：

1. 真实 AMap adapter 接入后，SDK MCP 错误包装是否足以表达配额、鉴权、超时、候选 POI 歧义和路线不可达。
2. `navigation_task` 进入更复杂手机视觉协同时，通知去重、抢播策略和多任务资源仲裁是否需要更明确的 SDK 公共能力。
3. `timer_task` 已使用 SDK 单进程通用调度器；生产化仍需继续观察进程重启恢复、租约和多实例防重能力。
4. 全双工实时语音真机验收时，端侧 AEC/VAD 和 `voice.realtime.user_interrupt` 的可观测字段是否足够排障。
5. 真实 iPhone 视觉插件需要继续验证长期运行时的帧率、温控、后台切换和权限恢复行为。
6. Python 3.13 环境下 `glass-playback` 发送 WAV 触发音频会因标准库 `audioop` 缺失失败；SDK 回放测试能力需要兼容 Python 3.13 或明确要求 Python 3.11。
