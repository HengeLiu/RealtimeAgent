# 旧代码迁移清单

## 1. 文档目的

本文档用于固化第二阶段的旧代码迁移范围、迁移批次、目标落位和当前状态。  
它的作用不是重复介绍架构，而是约束接下来每一批迁移具体迁什么、迁到哪里、如何验证。

---

## 2. 迁移总原则

- 新实现统一迁入 `nextgen/`
- 老文件先保留，不删除
- 旧项目原始文件当前统一位于 `origin-src/`
- 迁移优先抽取可复用逻辑，不优先复制旧入口
- 每一批迁移必须伴随最小测试或兼容验证
- 优先服务“寻找物体”黄金链路

---

## 4. 第一优先级迁移项

### 4.1 `asr_core.py`

优先迁移原因：

- 逻辑相对独立
- 纯函数和状态判断较多
- 易于补充对照测试
- 能直接服务服务器接入与任务触发链路

第二阶段目标：

- 迁移事件转字典逻辑
- 迁移句子提取逻辑
- 迁移中文热词归一化与匹配逻辑
- 暂不迁移与旧全局运行时深度耦合的异步识别控制

建议落位：

- `nextgen/apps/server/gateway/asr_support.py`

验证要求：

- 同输入事件对象下，解析文本结果保持一致
- 热词判断行为保持一致

---

### 4.2 `omni_client.py`

优先迁移原因：

- 文件体量小
- 结构清晰
- 能快速沉淀新的服务器智能体调用边界

第二阶段目标：

- 迁移 `OmniStreamPiece`
- 迁移请求消息构造逻辑
- 将真实 OpenAI 兼容客户端创建改为延迟初始化
- 第二阶段不要求真实联网调用

建议落位：

- `nextgen/apps/server/agent/omni_runtime.py`

验证要求：

- 构造出的请求体结构稳定
- 流式分片对象可被测试和后续网关调用

---

### 4.3 `yolomedia.py`

优先迁移原因：

- 与“寻找物体”直接相关
- 是第四阶段全链路打通的关键依赖

第二阶段目标：

- 优先抽取检测结果判断逻辑
- 优先抽取引导建议生成逻辑
- 暂不迁移 UI 叠加、音频播放、摄像头主循环

建议落位：

- `nextgen/apps/phone/skills/object_detection_skill.py`
- `nextgen/apps/phone/tasks/find_object_task.py`

验证要求：

- 给定检测输入后，可输出稳定的检测结果与引导建议

---

### 4.4 `app_main.py`

优先迁移原因：

- 旧主入口中包含服务器接入和状态广播的核心路径
- 是后续真实运行时装配的重要来源

第二阶段目标：

- 优先拆接入层辅助逻辑
- 优先拆 UI 文本广播与状态广播相关能力
- 优先拆与任务状态承接相关逻辑
- 暂不迁移大型启动副作用和完整 Web 服务入口

建议落位：

- `nextgen/apps/server/gateway/`
- `nextgen/apps/server/runtime/`
- `nextgen/apps/server/storage/`

验证要求：

- 迁移能力可以被 `ServerRuntimeApp` 装配
- 不依赖旧全局变量才能最小运行

---

## 5. 第二阶段暂缓迁移项

以下内容在第二阶段不作为优先落地目标：

- 旧导航工作流的深度模块化重构
- 真实硬件相机、麦克风、IMU 联调
- 前端页面与三维 IMU 可视化迁移
- 真实云服务联通的端到端测试

---
