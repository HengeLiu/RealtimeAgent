# 开发阶段规划与第一阶段范围

## 1. 文档目的

本文档用于明确整个项目的实现分阶段规划，并重点约束第一阶段的实现范围，防止代码实现偏离阶段目标。

---

## 2. 总体分阶段规划

### 第一阶段：整体架构搭建

目标：

- 完成新的整体代码骨架搭建
- 落地各种实体、模型、协议、抽象接口
- 建立三端目录结构
- 建立基础运行时骨架

这一阶段应完成：

- `nextgen/` 目录骨架
- 三端运行时主目录
- 共享层目录
- 公共数据模型
- 公共通讯协议
- 抽象接口与基础契约
- 任务、采集、执行、链路等核心对象定义

这一阶段不要求：

- 旧代码迁移完成
- 功能完整可运行
- 设备真实串联

---

### 第二阶段：旧代码迁移与兼容验证

目标：

- 将现有老代码中的可复用能力迁移到新结构中
- 通过测试确认迁移后的旧能力仍可运行

这一阶段应完成：

- 老代码能力拆分映射
- 迁移后的适配层或兼容层
- 最小可运行测试
- 对关键老功能进行回归验证

这一阶段不要求：

- 所有新模块逻辑都完成
- 所有硬件都真实串联

---

### 第三阶段：各模块独立实现逻辑细节

目标：

- 按模块逐步实现细节逻辑
- 保证模块可以独立开发、独立测试、独立替换

这一阶段应完成：

- `sensor_hub` 采集仲裁逻辑
- `executor_bus` 执行调度逻辑
- 三端 gateway 的连接与消息处理逻辑
- `background_task_center`、`local_task_center` 的状态机
- 各 Skills / MCP / 任务组件的具体逻辑

这一阶段不要求：

- 全部业务功能最终集成完成

---

### 第四阶段：基于“寻找物体”打通全链路

目标：

- 以“寻找物体”为第一个真实打通功能
- 将所有模块、协议、硬件、执行链路串起来
- 在真实设备上完成闭环验证

这一阶段应完成：

- 语音发起找物
- 服务器创建混合任务
- 手机执行检测
- 手机直发引导给眼镜
- 服务器记录任务状态
- 眼镜执行播报
- 任务完成收尾

---

## 3. 第一阶段的强约束范围

### 3.1 第一阶段必须完成

- 创建 `nextgen/` 顶层目录
- 建立 `glass / phone / server / shared` 的基础目录结构
- 落地模块空骨架与基础接口
- 落地数据模型定义
- 落地通讯协议定义
- 落地核心抽象接口

### 3.2 第一阶段允许使用占位实现

- 网关连接逻辑可先用 stub 或简化实现
- Skills / MCP 可先只保留注册接口
- 任务组件可先只保留生命周期空实现
- 旧代码可以先不迁移，只做挂载点和适配接口

### 3.3 第一阶段禁止事项

- 不允许在旧代码主入口上继续叠加新架构
- 不允许在没有统一模型和协议的情况下先写跨端业务逻辑
- 不允许为单个功能临时发明新的私有通信格式

---

## 4. 第一阶段交付标准

第一阶段完成时，应至少满足：

- 仓库中存在清晰的新目录骨架
- 三端运行时主目录存在
- 共享模型和协议目录存在
- 模块命名与文档一致
- 核心数据模型已有代码定义或等价 schema 定义
- 核心通信协议已有代码定义或等价 schema 定义
- 任务、采集、执行、状态等抽象接口已形成

---

## 5. 第二阶段进入条件

只有当以下条件满足时，才进入第二阶段：

- 第一阶段交付标准全部满足
- 目录结构已稳定
- 数据模型和协议草案没有重大未决问题
- 至少一条基础测试链路可跑通
