## 2. 总览说明

方向矫正是导航任务中的一个高频子能力，也可以独立触发。核心输入是：

- 眼镜 IMU
- 手机定位/GPS/罗盘
- 当前导航目标方向

输出是给眼镜的“向左/向右/对正”引导。

```plantuml

participant "task_components.heading_correction\n方向矫正组件" as HC #DDEBFF
participant "glass_gateway\n眼镜接入层" as GG #DFF3E3
participant "sensor_hub\n感知总线" as SH #DFF3E3

BTC -> SG: 下发方向矫正任务
SG -> PG: 转发给手机
PG -> HC: 启动方向矫正组件
PG -> GG: 请求 IMU 流
GG -> SH: 注册 IMU 采集请求
@enduml
```

## 4. 时序过程二：方向矫正闭环

```plantuml
@startuml
title 时序过程二：方向矫正闭环
autonumber
skinparam shadowing false

participant "sensor_hub\n感知总线" as SH #DFF3E3
participant "glass_gateway\n眼镜接入层" as GG #DFF3E3
participant "phone_gateway\n手机接入层" as PG #DDEBFF
participant "task_components.heading_correction\n方向矫正组件" as HC #DDEBFF
participant "executor_bus\n执行总线" as EB #DFF3E3
participant "server_gateway\n服务器接入层" as SG #FFF4CC

SH --> GG: 持续输出 IMU 数据
GG --> PG: 转发姿态信息
PG -> HC: 输入 IMU + GPS + 路径方向
HC -> HC: 计算偏角
HC -> GG: 直接发送“左转一点/右转一点/已对正”
GG -> EB: 播报方向引导
PG -> SG: 上报矫正状态
@enduml
```

---

## 5. 关键分支

- 若 GPS 漂移过大，可暂时退化为 IMU + 视觉辅助
- 若用户已对正，则进入导航主任务下一阶段
- 若长时间未对正，可通知服务器调整策略
