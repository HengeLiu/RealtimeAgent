## 2. 总览说明

该功能是一个“后台定时任务 + 二次能力调用”的组合模式：

1. 用户用自然语言定义检查间隔和检查提示词
2. 服务器创建一个周期性后台任务
3. 每到触发时间，服务器向眼镜发起抓拍请求
4. 服务器调用对应 Skill 或智能体判断画面变化
5. 若命中条件，通知眼镜或主智能体

## 3. 时序过程一：定时任务创建

```plantuml
@startuml

autonumber

participant "agent_center\n智能体中心" as AC #FFF4CC
participant "skills_registry\n技能注册中心" as SK #FFF4CC
participant "background_task_center\n后台任务中心" as BTC #FFF4CC
participant "state_log_store\n状态与日志存储" as LOG #FFF4CC

User -> SG: 请求“每三秒看一次桌上水杯有没有变化”
SG -> AC: 转交智能体
AC -> SK: 调用 create_scheduled_task
SK -> BTC: 创建定时检查 TaskSession
BTC -> LOG: 记录任务创建
@enduml
```

## 4. 时序过程二：周期触发与检查

```plantuml
@startuml
title 时序过程二：周期触发与检查
autonumber
skinparam shadowing false

participant "background_task_center\n后台任务中心" as BTC #FFF4CC
participant "server_gateway\n服务器接入层" as SG #FFF4CC
participant "glass_gateway\n眼镜接入层" as GG #DFF3E3
participant "sensor_hub\n感知总线" as SH #DFF3E3
participant "agent_center\n智能体中心" as AC #FFF4CC
participant "state_log_store\n状态与日志存储" as LOG #FFF4CC
participant "executor_bus\n执行总线" as EB #DFF3E3

loop 每个定时间隔触发
    BTC -> SG: 下发抓拍请求
    SG -> GG: 转发抓拍指令
    GG -> SH: 注册抓拍请求
    SH --> GG: 返回图片
    GG -> SG: 上传图片
    SG -> AC: 调用检查逻辑
    AC -> AC: 对比变化 / 判断是否命中
    alt 命中变化条件
        AC -> SG: 输出通知文案
        SG -> GG: 下发通知
        GG -> EB: 播报“检测到画面变化”
    else 未命中
        AC -> BTC: 更新检查状态
    end
    BTC -> LOG: 记录本次检查结果
end
@enduml
```

---

## 5. 关键分支

- 定时任务应当可复用任意其他 Skill
- 可以选择“只通知用户”或“同时通知主智能体”
- 长时间未命中时不应频繁打扰用户
