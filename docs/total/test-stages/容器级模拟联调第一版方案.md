# 容器级模拟联调第一版方案

## 1. 文档目的

本文档用于说明“容器级模拟”第一版的落地方式、当前范围和使用方法。

## 2. 当前实现目标

当前第一版重点是让眼镜、手机、服务器三端直接通过 WebSocket 长连接通信跑起来，并优先验证下面这些内容：

- 三端镜像可以统一构建
- 三端容器可以独立启动
- 容器共享状态目录和结果目录可以工作
- 三端可以直接完成一次真正的任务消息往返
- 标准 `case_id` 可以在容器环境中生成结构化结果

## 3. 当前已落地文件

当前已经落地：

- `deploy/container-sim/Dockerfile`
- `deploy/container-sim/docker-compose.yml`
- `scripts/run_simulated_runtime.py`
- `scripts/run_container_find_object_case.py`
- `nextgen/integration/container_sim/ws_client.py`
- `nextgen/integration/container_sim/runtime_ws_server.py`
- `nextgen/integration/container_sim/runtime_probe.py`
- `nextgen/integration/container_sim/case_runner.py`
- `nextgen/integration/container_sim/services.py`

## 4. 运行方式

当前推荐在仓库根目录执行：

```bash
docker compose -f deploy/container-sim/docker-compose.yml up --build
```

运行后将产生：

- `/shared/status/*.json`：三端探针文件
- `/shared/results/find_object_phone_center_001.json`：场景输出结果

## 5. 当前结果含义

当前阶段的容器级模拟结果可以证明：

- 三端配置隔离是可行的
- 测试数据挂载方式是可行的
- 标准 case 驱动方式是可行的
- 容器环境下的统一结果格式是可行的
- 三端直连 WebSocket 长连接消息往返链路是可行的
- 联调器当前只需与眼镜和服务器交互，不需要直接调用手机

但当前还不能证明：

- 真实网络边界下的协议链路已经成立
- 真实音频和图像回放已经成立
- 高吞吐流式传输已经成立

## 6. 当前技术取舍

本阶段采用了一个明确取舍：

- 三端容器通过探针文件暴露“运行体已就绪”
- 三端之间直接通过 WebSocket 长连接交换 RPC 消息
- 联调器通过眼镜注入语音，通过服务器注入单帧分析并读取任务结果
- 连续帧和音频流仍未升级为真正的流式媒体通道

这样做的目的是先把镜像、卷、配置、场景编号、结果产出和三端直连 WebSocket 协作这几件事稳定下来，再进入下一步连续帧和音频流的流式通信。

## 7. 下一步建议

容器级模拟第一版落地后，下一步建议按下面顺序推进：

1. 把当前 RPC 型 WebSocket 长连接升级为连续帧与音频流通道
2. 把当前探针文件同步升级为更完整的健康检查和状态快照
3. 再把找物中的连续帧和音频流改成真正流式传输
