# 标准测试数据规范

## 1. 文档目的

本文档用于定义模拟联调和真机联调阶段共用的标准测试数据组织方式。

本文档重点解决三个问题：

- 测试数据应该放在哪里
- 文件命名应该如何与 `case_id` 对齐
- 结构化标注数据与真实媒体文件如何共存

## 2. 当前目录结构

当前标准测试数据目录为：

- `testdata/voice/`
- `testdata/find_object/`
- `testdata/imu/`

其中：

- `voice/` 负责语音触发和状态查询相关数据
- `find_object/` 负责“寻找物体”相关数据
- `imu/` 负责姿态与转头类数据

## 3. 数据组织原则

### 3.1 统一以 case_id 为主键

所有数据都必须带有 `case_id`，并满足：

- JSON 清单中的 `case_id` 是唯一值
- 音频文件、图片目录、视频文件都应与 `case_id` 对齐
- 所有联调日志应打印 `case_id`

### 3.2 结构化数据与真实媒体文件分层维护

当前建议同时保留两类数据：

- 结构化数据
- 真实媒体文件

结构化数据用于：

- 快速回放
- 单元测试
- 集成测试
- 无硬件环境下的协议和状态机验证

真实媒体文件用于：

- I/O 模拟增强
- 混合联调
- 真机联调复现

### 3.3 真实媒体文件可以缺省，但规范不能缺省

当前仓库允许暂时不提交真实音频、图片、视频文件，但必须先提交：

- 目录结构
- 命名规范
- manifest 清单

这样后续新增真实文件时不会破坏既有联调脚本和场景编号。

## 4. 语音数据规范

当前语音数据包含：

- `voice_cases.json`
- `audio_manifest.json`
- `audio_samples/`

要求如下：

- `voice_cases.json` 负责语义输入定义
- `audio_manifest.json` 负责真实音频文件命名约束
- `audio_samples/` 负责存放真实音频文件

真实音频文件建议：

- 使用 `wav`
- 使用 `16k pcm`
- 文件名与 `case_id` 一致

## 5. 找物数据规范

当前找物数据包含：

- `find_object_cases.json`
- `media_manifest.json`
- `images/`
- `videos/`

要求如下：

- `find_object_cases.json` 负责结构化几何输入
- `media_manifest.json` 负责真实媒体文件命名约束
- `images/` 用于静态图片
- `videos/` 用于短视频或帧流来源

## 6. IMU 数据规范

当前 IMU 数据使用 `imu_cases.json` 管理。

每个 case 应至少包含：

- `case_id`
- `description`
- `samples`

每个 sample 应至少包含：

- `t`
- `yaw`
- `pitch`
- `roll`

## 7. 当前已落地状态

当前已经落地：

- `testdata/` 标准目录
- 语音 case 清单
- 找物 case 清单
- IMU case 清单
- 音频和媒体 manifest 清单
- 真实文件目录规范

当前尚未落地：

- 真实音频文件
- 真实图片文件
- 真实视频文件

## 8. 后续补数要求

后续补充真实媒体文件时，建议按以下顺序推进：

1. 先补 `voice_find_phone_001.wav`
2. 再补 `find_object_phone_center_001` 的静态图片
3. 再补 `find_object_phone_center_001.mp4`
4. 然后逐步补充其他标准 case
