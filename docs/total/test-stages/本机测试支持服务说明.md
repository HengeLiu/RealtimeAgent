# 本机测试支持服务说明

## 1. 文档目的

本文档用于说明新的本机多进程联调方式。

目标是：

- 不再依赖 Docker 容器
- 直接在本机以不同端口启动 server / glass / phone
- 通过一个测试支持服务统一查看状态、发送文本、发送图片、上传视频
- 通过测试支持服务触发对讲模式和实时对话模式

---

## 2. 启动方式

当前仓库已经提供以下启动脚本：

- [run_local_test_support_service.py](/Users/elio/dev/llm-project/OpenAIglasses_for_Navigation/scripts/run_local_test_support_service.py)

运行方式：

```bash
uv run python scripts/run_local_test_support_service.py
```

默认端口：

- 测试支持服务：`18400`
- server：`18490`
- glass：`18491`
- phone：`18492`

---

## 3. 当前能力

测试支持服务启动后会自动拉起：

- server 控制面进程
- glass 控制面进程
- phone 控制面进程

并提供一个 Web 页面：

- `http://127.0.0.1:18400/`

页面当前支持：

- 查看三端状态与服务器快照
- 创建找物长连接
- 向眼镜发送文本输入
- 触发对讲模式录音，再次点击结束录音并发送到服务器
- 触发实时对话模式，再次点击结束实时对话
- 向眼镜发送图片输入
- 在任务级连接建立后弹出视频上传窗口
- 上传视频并由眼镜通过 WebSocket 向手机模拟流式传输
- 将上传的图片/视频帧真正接入手机侧找物检测链路

---

## 4. 输入说明

### 4.1 文本输入

文本输入会通过测试支持服务转发给眼镜，再由眼镜生成结构化语音事件并上送服务器。

### 4.2 图片输入

图片输入会先保存到本地 `tmp/test-support/uploads/`，然后：

- 如果当前没有任务级连接，则只作为测试图片输入交给眼镜记录
- 如果当前已有任务级连接，则由眼镜将图片作为单帧图像发送给手机
- 手机收到单帧图像后会先做原始 JPEG 解码，再走轻量 OpenCV 启发式找物检测，最后复用现有找物任务组件生成引导建议

### 4.3 视频输入

视频输入仅在任务级连接建立后使用。

上传视频后：

- 测试支持服务将视频保存到本地
- 眼镜读取视频文件
- 眼镜按帧将图像通过任务级 WebSocket 发送给手机
- 手机对每帧做原始图像找物检测
- 手机返回引导建议给眼镜
- 眼镜对连续重复提示做去重，避免每帧都重复播报同一句话

### 4.4 对讲模式

测试支持页面上的“开始对讲录音”按钮采用 toggle 方式工作：

- 第一次点击：触发 glass 启动本机麦克风录音
- 第二次点击：停止录音，生成本地 WAV 文件
- glass 通过服务器创建一个 `push_to_talk` 语音会话
- 服务器调用百炼 ASR 转写音频文件
- 服务器调用对话模型生成回复
- 服务器调用百炼 TTS 将回复转成流式 PCM 音频
- 服务器通过语音 WebSocket 向 glass 下发音频块
- glass 通过本机喇叭播放音频

当前实现约束：

- glass 不接收 ASR 文本
- glass 只接收语音音频块和停止播放控制消息
- 对讲模式当前使用“录音完成后上传处理”的方式，不是边录边识别

### 4.5 实时对话模式

测试支持页面上的“开始实时对话”按钮同样采用 toggle 方式工作：

- 第一次点击：glass 创建 `realtime` 语音会话，并与服务器建立语音 WebSocket
- glass 使用本机麦克风持续采集 PCM 音频块并发送给服务器
- 服务器通过百炼实时 ASR 处理音频流
- 当 ASR 产出一句最终结果后，服务器启动一轮对话回复生成
- 服务器在生成回复时，会把已经形成可播报片段的文本送入百炼 TTS
- TTS 返回的流式 PCM 音频通过 WebSocket 持续下发给 glass
- glass 持续播放音频
- 如果用户再次说话，服务器会中断上一轮播报，并把上一轮未播完的 assistant 内容与新的 user 内容一起继续进入后续对话
- 第二次点击：glass 主动关闭实时语音会话

## 5. 日志说明

当前已经为每个运行单元单独落盘日志：

- 服务器日志：
  - `nextgen/apps/server/logs/server-runtime.log`
- 眼镜日志：
  - `nextgen/apps/glass/logs/glass-runtime.log`
- 手机日志：
  - `nextgen/apps/phone/logs/phone-runtime.log`
- 测试支持服务日志：
  - `nextgen/integration/test_support/logs/test-support.log`

日志中当前会记录：

- 设备注册与心跳
- 任务创建
- 长连接准备、连接、关闭、断链、恢复
- 对讲模式录音开始、录音结束、文件转写、TTS 下发
- 实时语音会话开始、音频块上送、TTS 音频块播放、打断事件
- 文本输入、图片输入、视频流发送
- 手机收到帧、单帧检测结果和引导建议
- 眼镜执行播报和重复提示去重结果

---

## 6. 当前结论

新的本机联调方式已经从“容器模拟”收敛到：

- 本机多进程
- 测试支持服务统一入口
- Web 页面注入输入与查看状态
- 语音对讲和实时对话的本机联调入口
- 三端独立日志落盘

这更适合当前真实开发和联调阶段。
