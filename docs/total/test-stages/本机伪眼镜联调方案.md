# 本机伪眼镜联调方案

## 1. 文档目的

本文档用于说明如何使用当前电脑上的相机、麦克风和喇叭，临时充当 `glass` 运行时的真实硬件输入输出，作为真眼镜硬件到位前的联调方案。

---

## 2. 当前已落地能力

当前仓库已经提供以下本机硬件适配能力：

- 本机摄像头抓帧
- 本机麦克风录制短音频
- 本机喇叭播报文本

对应代码：

- [local_devices.py](/Users/elio/dev/llm-project/OpenAIglasses_for_Navigation/nextgen/apps/glass/hardware/local_devices.py)
- [sensor_hub.py](/Users/elio/dev/llm-project/OpenAIglasses_for_Navigation/nextgen/apps/glass/sensors/sensor_hub.py)
- [device_control.py](/Users/elio/dev/llm-project/OpenAIglasses_for_Navigation/nextgen/apps/glass/execution/device_control.py)
- [app.py](/Users/elio/dev/llm-project/OpenAIglasses_for_Navigation/nextgen/apps/glass/runtime/app.py)

---

## 3. 当前能力边界

这套方案当前适合做：

- 验证本机摄像头是否能被 `glass` 运行时接入
- 验证本机麦克风是否能录制测试音频
- 验证引导播报是否能通过本机喇叭真正发声

这套方案当前还不能直接替代：

- 真正的 IMU
- 真正的深度相机
- 基于麦克风实时 ASR 的完整语音链路
- 基于摄像头原始图像的真实找物检测链路

说明：

当前“找物”数据面仍然发送结构化单帧分析输入，而不是原始 JPEG 图像帧。  
因此本机摄像头已经可以接入 `glass`，但若要让它直接服务找物，还需要后续把数据面从“结构化分析输入”升级成“真实图像帧”。

---

## 4. 本机探测脚本

当前仓库已经提供一个可直接运行的探测脚本：

- [run_local_glass_hardware_probe.py](/Users/elio/dev/llm-project/OpenAIglasses_for_Navigation/scripts/run_local_glass_hardware_probe.py)

运行方式：

```bash
uv run python scripts/run_local_glass_hardware_probe.py
```

可选参数：

```bash
uv run python scripts/run_local_glass_hardware_probe.py \
  --camera-index 0 \
  --camera-output tmp/glass-probe/camera.jpg \
  --audio-output tmp/glass-probe/mic.wav \
  --record-seconds 2 \
  --speak-text "本机伪眼镜喇叭测试"
```

---

## 5. 运行结果说明

脚本会输出一个 JSON 结果，包含：

- `camera`
  - 摄像头编号
  - 分辨率
  - JPEG 大小
  - 输出文件路径
- `microphone`
  - 采样率
  - 声道数
  - 录音时长
  - 输出 WAV 路径
- `speaker`
  - 当前播报后端
  - 进程号
  - 播报文本

---

## 6. 当前建议使用方式

建议按以下顺序使用本机伪眼镜方案：

1. 先运行硬件探测脚本，确认相机、麦克风和喇叭可用。
2. 再把本机摄像头接入后续的真实图像帧数据面实验。
3. 最后再尝试把本机麦克风接入 VAD / ASR 链路。

原因：

- 相机和喇叭的接入成本低、收益高
- 麦克风虽然已经能录音，但要进入实时 ASR 链路还需要更多后续实现

---

## 7. 当前结论

截至当前代码状态，本机已经可以作为“伪眼镜”接入：

- 摄像头
- 麦克风
- 喇叭

这使得后续联调可以从“全模拟”进一步推进到“半真实硬件输入输出”，并为真眼镜设备到位前的验证提供更贴近真实的中间阶段。
