# 统一通讯协议草案

## 1. 文档目的

本文档定义系统在眼镜、手机、服务器三端之间的统一通信协议草案，用于约束：

- 控制面消息如何组织
- 数据面消息如何组织
- 任务级点对点通道如何协商
- 状态、事件、指令、错误、确认如何表达

本文档建立在 [统一数据模型草案.md](/Users/elio/dev/llm-project/OpenAIglasses_for_Navigation/docs/total/统一数据模型草案.md) 之上。数据对象本身不在本文重复定义，本文件重点定义“这些对象如何被包进消息里发送”。

---

## 2. 设计目标

- 一套协议同时覆盖眼镜、手机、服务器三端
- 控制面与数据面分离，但共用同一套基础包络结构
- 支持任务级点对点链路
- 支持 ACK、重试、错误回传
- 支持渐进式实现，不要求第一期就覆盖所有高级能力

---

## 3. 通信分层

### 3.1 控制面

控制面默认经服务器中转，负责：

- 设备注册
- 心跳
- 任务创建
- 指令下发
- 状态回传
- 日志追踪
- 任务级点对点通道协商

典型路径：

- 眼镜 <-> 服务器
- 手机 <-> 服务器

---

### 3.2 数据面

数据面负责大流量、低延迟数据传输，优先用于：

- 图片帧
- 视频流
- 深度帧
- 音频片段

数据面支持两种模式：

- `relay`
  - 经服务器中转
- `peer`
  - 眼镜与手机任务级直连

第一期可以先支持：

- 控制面固定走服务器
- 数据面支持 `relay` 和 `peer` 两种策略，但实现上可先从 `relay` 起步

---

## 4. 协议总体结构

### 4.1 消息包络 `Envelope`

所有控制面消息都建议统一封装为 `Envelope`。

#### 示例

```json
{
  "protocol_version": "0.1.0",
  "message_id": "msg_01JQXYZ123ABC",
  "message_type": "task.command.start",
  "channel": "control",
  "timestamp": "2026-04-02T11:00:00+08:00",
  "trace_id": "trace_01JQXYZ999",
  "source": {
    "runtime": "server",
    "device_id": "server-main"
  },
  "target": {
    "runtime": "phone",
    "device_id": "phone-001"
  },
  "session_id": "tasksess_20260402_0001",
  "requires_ack": true,
  "payload": {}
}
```

#### 字段说明

- `protocol_version`
  - 协议版本
- `message_id`
  - 消息唯一 ID
- `message_type`
  - 消息类型
- `channel`
  - 通道类型，通常为 `control` 或 `data`
- `timestamp`
  - 发送时间
- `trace_id`
  - 用于同一条业务链路追踪
- `source`
  - 发送方
- `target`
  - 接收方
- `session_id`
  - 所属任务实例，可为空
- `requires_ack`
  - 是否要求接收方 ACK
- `payload`
  - 业务载荷

---

### 4.2 `SourceTargetRef`

#### 示例

```json
{
  "runtime": "glass",
  "device_id": "glass-001"
}
```

#### 字段说明

- `runtime`
  - 发送或接收运行时
- `device_id`
  - 设备 ID

---

## 5. 通道类型

### 5.1 `ChannelType`

#### 建议枚举值

```json
["control", "data"]
```

---

### 5.2 `TransportMode`

#### 建议枚举值

```json
["relay", "peer"]
```

#### 说明

- `relay`
  - 数据经服务器中转
- `peer`
  - 设备与设备之间任务级直连

## 6. 消息类型体系

### 6.1 设计原则

建议消息类型采用分层命名：

```text
{domain}.{kind}.{action}
```

例如：

- `device.lifecycle.hello`
- `task.command.start`
- `task.state.update`
- `capture.request.create`
- `execution.request.play`
- `stream.frame.push`

---

### 6.2 推荐消息大类

- `device.*`
  - 设备接入、心跳、在线状态
- `event.*`
  - 结构化事件
- `task.*`
  - 任务创建、指令、状态
- `capture.*`
  - 采集请求、采集授权、采集数据摘要
- `execution.*`
  - 播报、震动等执行请求和反馈
- `stream.*`
  - 数据面帧消息
- `link.*`
  - 点对点通道协商
- `ack.*`
  - ACK 确认
- `error.*`
  - 错误消息

## 7. 设备接入协议

### 7.1 设备上线 `device.lifecycle.hello`

#### 示例

```json
{
  "protocol_version": "0.1.0",
  "message_id": "msg_hello_001",
  "message_type": "device.lifecycle.hello",
  "channel": "control",
  "timestamp": "2026-04-02T11:00:00+08:00",
  "source": {
    "runtime": "glass",
    "device_id": "glass-001"
  },
  "target": {
    "runtime": "server",
    "device_id": "server-main"
  },
  "requires_ack": true,
  "payload": {
    "device_info": {
      "device_id": "glass-001",
      "runtime": "glass",
      "display_name": "主眼镜",
      "online": true,
      "capabilities": ["rgb_camera", "imu", "speaker", "vibrator"]
    }
  }
}
```

---

### 7.2 心跳 `device.lifecycle.heartbeat`

#### 用途

- 维持在线状态
- 更新设备最近状态摘要

#### 载荷建议

```json
{
  "status": "online",
  "battery_level": 0.72,
  "active_session_ids": ["tasksess_20260402_0001"]
}
```

## 9. 任务控制协议

### 9.1 启动任务 `task.command.start`

#### 说明

服务器向眼镜或手机下发任务启动指令。

#### 示例

```json
{
  "message_type": "task.command.start",
  "channel": "control",
  "session_id": "tasksess_20260402_0001",
  "source": {
    "runtime": "server",
    "device_id": "server-main"
  },
  "target": {
    "runtime": "phone",
    "device_id": "phone-001"
  },
  "requires_ack": true,
  "payload": {
    "task_name": "find_object",
    "phase": "starting",
    "input": {
      "target_name": "手机"
    }
  }
}
```

---

### 9.2 停止任务 `task.command.stop`

#### 示例

```json
{
  "message_type": "task.command.stop",
  "channel": "control",
  "session_id": "tasksess_20260402_0001",
  "payload": {
    "reason": "completed"
  }
}
```

---

### 9.3 任务状态上报 `task.state.update`

#### 说明

用于手机或眼镜向服务器回传任务状态。

#### 示例

```json

  "message_type": "task.state.update",
  "channel": "control",
  "session_id": "tasksess_20260402_0001",
  "source": {
    "runtime": "phone",
    "device_id": "phone-001"
  },
  "target": {
    "runtime": "server",
    "device_id": "server-main"
  },
  "payload": {
    "task_state_event": {
      "event_type": "task_state_changed",
      "session_id": "tasksess_20260402_0001",
      "payload": {
        "task_name": "find_object",

        "phase": "guiding",
        "summary": {

  }
}
```

## 10. 采集控制协议

### 10.1 创建采集请求 `capture.request.create`

#### 说明

用于任务在控制面中注册采集请求。

#### 示例

```json
{
  "message_type": "capture.request.create",
  "channel": "control",
  "session_id": "tasksess_20260402_0001",
  "payload": {
    "capture_request": {
      "request_id": "capreq_0001",
      "session_id": "tasksess_20260402_0001",
      "sensor": "rgb_camera",
      "mode": "stream",
      "priority": "high",
      "profile": {
        "fps": 5,
        "resolution": {
          "width": 640,
          "height": 480
        },
        "quality": "medium"
      }
    }
  }
}
```

---

### 10.2 采集授权回执 `capture.request.granted`

#### 说明

由 `sensor_hub` 或眼镜接入层返回实际生效采集配置。

#### 示例

```json
{
  "message_type": "capture.request.granted",
  "channel": "control",
  "session_id": "tasksess_20260402_0001",
  "payload": {
    "capture_grant": {
      "request_id": "capreq_0001",
      "granted": true,
      "effective_profile": {
        "fps": 4,
        "resolution": {
          "width": 640,
          "height": 480
        },
        "quality": "medium"
      },
      "reason": "shared_with_existing_stream"
    }
  }
}
```

---

### 10.3 取消采集请求 `capture.request.cancel`

#### 说明

任务结束后释放采集资源。

#### 示例

```json
{
  "message_type": "capture.request.cancel",
  "channel": "control",
  "session_id": "tasksess_20260402_0001",
  "payload": {
    "request_id": "capreq_0001"
  }
}
```

## 12. 数据面协议

### 12.1 设计目标

数据面用于传输大流量二进制或高频帧数据，不建议和控制面共用重型 JSON 结构。

但为了统一语义，仍建议有一层轻量头部。

---

### 12.2 数据帧头 `DataFrameHeader`

#### 示例

```json
{
  "protocol_version": "0.1.0",
  "message_id": "msg_frame_0001",
  "message_type": "stream.frame.push",
  "channel": "data",
  "transport_mode": "peer",
  "session_id": "tasksess_20260402_0001",
  "source": {
    "runtime": "glass",
    "device_id": "glass-001"
  },
  "target": {
    "runtime": "phone",
    "device_id": "phone-001"
  },
  "payload_meta": {
    "stream_type": "image/jpeg",
    "frame_index": 120,
    "timestamp_ms": 1743563200123
  }
}
```

#### 说明

- `payload_meta`
  - 描述后续二进制负载
- 实际图片或音频字节建议跟随头部发送，或在同一 websocket binary frame 中组合

---

### 12.3 数据面消息类型

#### 建议枚举值

```json
[
  "stream.open",
  "stream.frame.push",
  "stream.frame.pull",
  "stream.close"
]
```

---

### 12.4 `stream.open`

#### 用途

- 开启一个任务级数据通道
- 说明数据类型和方向

#### 示例

```json
{
  "message_type": "stream.open",
  "channel": "control",
  "session_id": "tasksess_20260402_0001",
  "payload": {
    "stream_id": "stream_0001",
    "transport_mode": "peer",
    "stream_type": "image/jpeg",
    "direction": "glass_to_phone"
  }
}
```

---

### 12.5 `stream.frame.pull`

#### 用途

手机端按需向眼镜请求下一帧。

#### 示例

```json
{
  "message_type": "stream.frame.pull",
  "channel": "data",
  "session_id": "tasksess_20260402_0001",
  "payload_meta": {
    "stream_id": "stream_0001",
    "request_next": true
  }
}
```

## 13. 点对点通道协商协议

### 13.1 设计说明

点对点通道协商仍建议走控制面，由服务器发起或批准。

流程建议：

1. 服务器下发 `link.peer.prepare`
2. 眼镜和手机分别返回可用连接信息
3. 服务器决定使用 `peer` 还是 `relay`
4. 三端确认后开始数据传输

---

### 13.2 `link.peer.prepare`

#### 示例

```json
{
  "message_type": "link.peer.prepare",
  "channel": "control",
  "session_id": "tasksess_20260402_0001",
  "payload": {
    "peer_with": {
      "runtime": "phone",
      "device_id": "phone-001"
    },
    "preferred_transport": "peer",
    "stream_type": "image/jpeg"
  }
}
```

---

### 13.3 `link.peer.ready`

#### 示例

```json
{
  "message_type": "link.peer.ready",
  "channel": "control",
  "session_id": "tasksess_20260402_0001",
  "payload": {
    "transport_mode": "peer",
    "endpoint": {
      "scheme": "ws",
      "url": "ws://device.local/peer/tasksess_20260402_0001"
    }
  }
}
```

## 14. ACK 与错误协议

### 14.1 `ack.message`

#### 用途

- 对要求确认的控制面消息进行确认

#### 示例

```json
{
  "message_type": "ack.message",
  "channel": "control",
  "payload": {
    "acked_message_id": "msg_01JQXYZ123ABC",
    "status": "ok"
  }
}
```

---

### 14.2 `error.message`

#### 用途

- 表示消息处理失败
- 携带标准错误对象

#### 示例

```json
{
  "message_type": "error.message",
  "channel": "control",
  "payload": {
    "failed_message_id": "msg_01JQXYZ123ABC",
    "error": {
      "code": "CAMERA_BUSY",
      "message": "相机当前被更高优先级任务占用",
      "retryable": true
    }
  }
}
```

---

### 14.3 ACK 策略建议

- 设备注册、任务创建、任务启动、采集请求、链路协商必须 ACK
- 高频状态上报可不强制 ACK
- 数据帧默认不逐帧 ACK，避免吞吐受限

## 15. “寻找物体”案例在协议上的关键约束

对于“寻找物体”这个黄金案例，协议上要明确以下规则：

1. 语音输入必须走：
   - `event.voice.report`

2. 服务器创建任务后，启动任务用：
   - `task.command.start`

3. 眼镜相机采集请求用：
   - `capture.request.create`

4. 手机请求下一帧、眼镜推图片用：
   - `stream.frame.pull`
   - `stream.frame.push`

5. 手机给眼镜的引导建议，不经过服务器转发，可直接走：
   - `execution.request.play`
   - 或 `task.hint.direct`

6. 手机给服务器只回状态，不回完整引导建议，使用：
   - `task.state.update`

7. 任务完成后释放采集和数据流：
   - `capture.request.cancel`
   - `stream.close`
   - `task.command.stop`
