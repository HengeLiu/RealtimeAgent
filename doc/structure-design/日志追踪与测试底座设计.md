# 日志追踪与测试底座设计

## 1. 文档目标

本文定义第一阶段的可观测性与测试底座，包括日志、追踪 ID、结构化事件、联调 mock 和最小自动化测试要求。

## 2. 设计目标

- 让关键链路可排障
- 让跨端协同可追踪
- 让协议与状态机具备稳定测试基线
- 自动化测试优先使用 Mock，而不是完整模拟客户端

## 3. 日志设计

### 3.1 日志类型

- 接入日志
- 协议日志
- 任务日志
- Agent 运行时日志
- Skill / MCP 调用日志
- 错误日志

### 3.2 关键字段

每条关键日志建议至少包含：

- `timestamp`
- `level`
- `trace_id`
- `message_id`
- `task_id`
- `device_id`
- `module`
- `event_name`

### 3.3 日志原则

- 尽量结构化
- 不打印大体积原始媒体内容
- 不吞异常上下文

## 4. 追踪设计

统一使用：

- `trace_id`
- `message_id`
- `correlation_id`
- `task_id`

目标：

- 从用户输入追到设备动作
- 从任务创建追到任务完成

## 5. Mock 与联调工具

第一阶段建议建设：

- Mock Device Session
- Fake Gateway / Fake Transport
- Stub Skill / Stub MCP
- 消息抓包与回放工具
- 任务状态查询 CLI

说明：

- 自动化测试优先使用 Mock 数据、Fake 连接对象和 Stub 能力提供者。
- 第一阶段不需要为了测试去完整实现一套假眼镜应用或假手机应用。
- 只有少量联调测试才需要最小模拟客户端。

## 6. 测试金字塔

### 6.1 单元测试

- 协议模型
- 编解码器
- 状态机
- 注册表

### 6.2 集成测试

- 设备注册
- 消息路由
- TaskManager
- Agent 调用 Skill

### 6.3 联调测试

- 最小眼镜模拟端接入测试
- 非实时语音问答闭环
- 手机视频流建链闭环

这里的“最小眼镜模拟端”是轻量联调工具，不是完整客户端复制品。

## 7. 第一阶段最低测试要求

- `Envelope` 编解码测试
- `TaskStateMachine` 测试
- `ConnectionManager` 测试
- `SkillRegistry` 测试
- 设备注册集成测试
