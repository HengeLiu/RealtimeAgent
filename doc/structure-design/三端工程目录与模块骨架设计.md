# 三端工程目录与模块骨架设计

## 1. 文档目标

本文将《统一协议与数据模型设计》映射到实际工程目录与模块骨架，明确 `server`、`phone`、`glass` 三端的代码组织方式、模块依赖方向、抽象类位置和初始化顺序。

本文重点解决：

- 三端代码目录如何统一规划。
- 各层代码应放在哪一层。
- 协议、API、Core、Skill、Task、Infra 的依赖边界如何约束。
- 第一阶段应该先生成哪些骨架文件与抽象接口。

## 2. 总体设计原则

### 2.1 同构优先

- 三端尽量保持相似的模块命名。
- 相同职责尽量使用相同目录名。

### 2.2 依赖单向

允许的依赖方向：

- `protocol -> 无外部业务依赖`
- `infra -> protocol`
- `api -> protocol + infra`
- `core -> protocol + infra + api 抽象`
- `skill -> protocol + infra + core 抽象`
- `task -> protocol + infra + skill + core 抽象`
- `app/bootstrap -> 组合全部模块`

禁止的依赖方向：

- `protocol` 依赖业务模块
- `skill` 反向依赖具体 `task`
- `api` 直接编排复杂业务流程

### 2.3 先抽象后实现

- 第一阶段先建立接口、枚举、数据结构、状态机和模块注册机制。
- 业务实现可以后补，但骨架命名必须先稳定。

## 3. 顶层目录建议

仓库建议保持以下顶层结构：

- `doc/`
- `server/`
- `phone/`
- `glass/`
- `script/`

三端统一采用：

- `src/` 存放主代码
- `test/` 存放自动化测试
- `doc/` 存放本端说明文档

## 4.2 模块职责

### `app/`

职责：

- 应用启动入口
- 依赖装配
- 配置加载
- 生命周期管理

第一阶段建议文件：

- `main.py`
- `bootstrap.py`
- `container.py`

### `protocol/`

职责：

- 统一数据模型
- 消息包结构
- 枚举
- 编解码器

第一阶段建议文件：

- `models/device.py`
- `models/task.py`
- `models/session.py`
- `models/media.py`
- `models/error.py`
- `messages/envelope.py`
- `enums/message_type.py`
- `codec/json_codec.py`

### `api/`

职责：

- 长连接接入
- 消息接收与发送
- 路由分发
- ACK 处理
- 连接会话管理

第一阶段建议文件：

- `gateway/ws_gateway.py`
- `router/message_router.py`
- `handlers/system_handler.py`
- `handlers/audio_handler.py`
- `handlers/task_handler.py`
- `session/connection_session.py`

### `agent_core/`

职责：

- 管理对话主循环
- 管理模型调用
- 管理上下文
- 调用 Tool / Skill

第一阶段建议文件：

- `runtime/agent_runtime.py`
- `context/conversation_context.py`
- `model_adapter/base.py`
- `model_adapter/bailian_adapter.py`
- `tool_registry/registry.py`

### `backend_task_core/`

职责：

- 任务生命周期管理
- 任务事件派发
- 任务注册与查询

第一阶段建议文件：

- `manager/task_manager.py`
- `registry/task_registry.py`
- `state_machine/task_state_machine.py`
- `scheduler/task_scheduler.py`
- `event_bus/task_event_bus.py`

### `skill/`

职责：

- Skill 抽象
- Skill 注册
- 内置 Skill 实现

第一阶段建议文件：

- `base/skill_base.py`
- `base/skill_result.py`
- `registry/skill_registry.py`
- `builtin/camera_capture_skill.py`
- `builtin/audio_play_skill.py`
- `builtin/task_manage_skill.py`

### `task/`

职责：

- 任务模板抽象
- 任务模板实现

第一阶段建议文件：

- `base/task_base.py`
- `base/task_context.py`
- `templates/timer_task.py`
- `templates/navigation_task.py`
- `templates/photo_interpret_task.py`

### `mcp/`

职责：

- 外部服务适配抽象
- MCP 注册与调用

第一阶段建议文件：

- `base/mcp_adapter.py`
- `registry/mcp_registry.py`
- `adapters/amap_adapter.py`

### `infra/`

职责：

- 配置
- 日志
- 错误
- 通用工具
- 时间与 ID

第一阶段建议文件：

- `config/settings.py`
- `logging/logger.py`
- `errors/error_codes.py`
- `idgen/id_generator.py`
- `clock/system_clock.py`

## 5.2 模块职责

### `app/`

- 应用启动
- 依赖注入
- 页面路由初始化

### `protocol/`

- 与服务器统一字段和消息模型

### `api/`

- 与服务器建立长连接
- 承接命令下发
- 上报任务状态与事件

### `backend_task_core/`

- 承载本地长生命周期任务
- 管理视频流接收、YOLO 推理等任务实例

### `skill/`

- 封装本地原子能力
- 例如本地 YOLO、视频接收、ASR

### `task/`

- 手机本地任务模板
- 如 `video_link_receiver_task`

### `ui/`

- 联调页面
- 视频流回显页面
- 设备状态页面

### `infra/`

- 配置、日志、网络、错误处理

## 8. 模块初始化顺序

服务器建议初始化顺序：

1. `infra`
2. `protocol`
3. `api`
4. `skill registry`
5. `mcp registry`
6. `backend_task_core`
7. `agent_core`
8. `app bootstrap`

手机建议初始化顺序：

1. `infra`
2. `protocol`
3. `api`
4. `skill registry`
5. `backend_task_core`
6. `ui`

1. `infra`
2. `protocol`
3. `sensor`
4. `actuator`
5. `sensor_hub`
6. `actuator_hub`

## 10. 测试目录规范

- 协议模型测试放入 `test/protocol`
- 状态机测试放入 `test/<module>`
- 跨模块集成测试放入 `test/integration`

第一阶段建议至少具备：

- `Envelope` 编解码测试
- `TaskStateMachine` 测试
- `MessageRouter` 测试
- 设备注册集成测试

## 11. 代码约束

- 所有跨端字段名必须与《统一协议与数据模型设计》一致。
- 不允许在业务模块重复定义协议字段。
- 所有端内模块注册都必须通过显式注册表实现。
- 第一阶段不引入过度复杂的插件系统，优先采用简单注册机制。
