## 4. 四类能力的最终定义

### 4.1 Tool

`Tool` 是一次调用即可完成的原子能力。

代码层要求：

1. 实现一个执行类或执行函数。
2. 提供输入模型。
3. 提供输出模型。
4. 注册到 `ToolRegistry`。
5. 由 `AgentFacade` 统一转换成 OpenAI Agents SDK 可调用工具。

### 4.2 Skill

当前阶段 `Skill = 业务型高级 Tool`。

代码层要求：

1. Skill 仍然对外表现为一个 Tool。
2. 内部可以组合多个 Tool、MCP 或任务接口。
3. 不单独维护长期状态。
4. 不自己实现独立循环。

### 4.3 MCP

`MCP` 是远程工具服务接入层。

代码层要求：

1. 远程服务的接入与注册在 `agent_core/mcp/` 下完成。
2. 复杂业务流程不要写在 MCP Adapter 中。
3. MCP 返回值必须先转成项目内部统一数据结构，再交给 Tool、Skill 或 Agent 使用。

### 4.4 Task

`Task` 是未启动的后台任务模板代码。

代码层要求：

1. 每个 `Task` 必须有 `TaskSpec`。
2. 每个 `Task` 必须实现标准运行入口。
3. 每个 `Task` 必须通过 `TaskRegistry` 注册。
4. 所有后台任务实例都由 `backend-task-core` 创建为 `TaskRuntime`。

## 5. 统一输入输出协议

### 5.1 为什么必须统一协议

如果每个开发者都随意返回 `dict`，后面会出现三个问题：

1. OpenAI Tool schema 难以稳定生成。
2. `agent-core` 和 `backend-task-core` 之间的边界会漂。
3. 测试和日志无法统一。

因此项目内统一要求：

1. Tool 输入输出使用明确模型。
2. Skill 输入输出使用明确模型。
3. Task 输入、状态、事件使用明确模型。
4. 对外跨模块传递的数据必须是可 JSON 序列化的基础类型。
5. 所有跨模块模型在真正传递时，统一使用 `model_dump()` 后的结果。

### 5.2 推荐模型基类

推荐统一使用 `pydantic.BaseModel` 作为输入输出模型基类。

原因：

1. 方便校验输入。
2. 方便生成 schema。
3. 方便和 OpenAI Agents SDK 对接。

建议定义以下基础模型。

```python
from __future__ import annotations

from typing import Any, Literal

from pydantic import BaseModel, Field


class CapabilityError(BaseModel):
    """统一能力错误模型。"""

    code: str = Field(description="稳定错误码")
    message: str = Field(description="面向日志的错误信息")
    user_message: str = Field(description="面向用户的安全文案")
    retryable: bool = Field(default=False, description="是否允许重试")
    details: dict[str, Any] = Field(default_factory=dict, description="附加错误详情")


class CapabilityResult(BaseModel):
    """统一能力执行结果。"""

    ok: bool = Field(description="本次执行是否成功")
    data: dict[str, Any] = Field(default_factory=dict, description="成功结果")
    error: CapabilityError | None = Field(default=None, description="失败时错误")
    asset_refs: list[str] = Field(default_factory=list, description="关联资产引用")
    task_refs: list[str] = Field(default_factory=list, description="关联任务引用")


class ToolContext(BaseModel):
    """Tool 执行上下文。"""

    session_id: str
    device_id: str
    trace_id: str
    task_id: str | None = None


class TaskEvent(BaseModel):
    """任务事件模型。"""

    event_id: str
    event_name: str
    task_id: str
    task_type: str
    session_id: str
    device_id: str
    priority: Literal["low", "normal", "high", "critical"] = "normal"
    payload: dict[str, Any] = Field(default_factory=dict)
```

这些模型建议统一放在：

1. `server/src/agent_core/models/capability_models.py`
2. `server/src/backend_task_core/models.py`

### 5.3 严格校验规则

每次能力执行都必须满足下面规则：

1. 输入进入执行函数前，先用 `input_model.model_validate(...)` 校验。
2. 成功结果返回前，先用 `output_model.model_validate(result.data)` 校验。
3. `Task` 创建前，先用 `TaskSpec.input_model.model_validate(input)` 校验。
4. `TaskEvent` 发布前，先构造标准 `TaskEvent` 模型。

禁止写法：

1. 直接把未校验的 `dict` 传给 Tool。
2. 直接把未校验的 `dict` 返回给 Agent。
3. Task 里随意拼一个字段不固定的事件对象。

## 6. Tool 的具体写法

### 6.1 必须实现的类

每个 Tool 至少要有：

1. 输入模型
2. 输出模型
3. `ToolSpec`
4. 执行类 `BaseTool` 的子类
5. 注册代码

### 6.2 推荐基类

```python
from __future__ import annotations

from abc import ABC, abstractmethod
from typing import Any, ClassVar

from pydantic import BaseModel

from agent_core.models.capability_models import CapabilityResult, ToolContext


class ToolSpec(BaseModel):
    """Tool 元信息。"""

    name: str
    description: str
    input_model: type[BaseModel]
    output_model: type[BaseModel]
    tags: list[str] = []
    visible_to_model: bool = True


class BaseTool(ABC):
    """所有 Tool 的统一基类。"""

    spec: ClassVar[ToolSpec]

    @abstractmethod
    async def run(self, ctx: ToolContext, input_data: BaseModel) -> CapabilityResult:
        """执行 Tool 并返回统一结果。"""
        raise NotImplementedError
```

建议放到：

1. `server/src/agent_core/tools/base.py`

### 6.3 Tool 注册入口

`ToolRegistry` 负责：

1. 注册 Tool 类。
2. 根据名称查找 Tool。
3. 转成 OpenAI Agents SDK 可调用工具。

建议接口：

```python
from agents import function_tool


class ToolRegistry:
    """Tool 注册表。"""

    def register(self, tool_cls: type[BaseTool]) -> None:
        ...

    def get(self, name: str) -> type[BaseTool]:
        ...

    def build_openai_tools(self) -> list[Any]:
        ...
```

推荐实现要点：

1. `register()` 内部统一检查 `tool_cls.spec` 是否存在。
2. `build_openai_tools()` 内部统一把 `BaseTool.run(...)` 包装成 OpenAI Agents SDK 的 `function_tool(...)`。
3. OpenAI SDK 只在注册表或 `AgentFacade` 中使用，业务代码不要直接依赖。

建议放到：

1. `server/src/agent_core/tools/registry.py`

### 6.4 Tool 示例

下面是一个完整的 `query_device_state` Tool 骨架。

```python
from __future__ import annotations

from pydantic import BaseModel, Field

from agent_core.models.capability_models import CapabilityResult, ToolContext
from agent_core.skills.base import BaseSkill, SkillSpec
from agent_core.tools.base import ToolSpec


class QueryDeviceStateInput(BaseModel):
    """查询设备状态的输入参数。"""

    device_id: str = Field(description="设备唯一标识")


class QueryDeviceStateOutput(BaseModel):
    """查询设备状态的输出结构。"""

    online: bool = Field(description="设备是否在线")
    battery_level: int | None = Field(default=None, description="设备电量百分比")
    mode: str | None = Field(default=None, description="设备当前模式")


class QueryDeviceStateTool(BaseTool):
    """查询设备当前运行状态。"""

    spec = ToolSpec(
        name="query_device_state",
        description="查询眼镜设备当前在线状态、电量和运行模式",
        input_model=QueryDeviceStateInput,
        output_model=QueryDeviceStateOutput,
        tags=["device", "status"],
    )

    async def run(self, ctx: ToolContext, input_data: QueryDeviceStateInput) -> CapabilityResult:
        """查询设备状态并返回统一结构。"""

        device_state = {
            "online": True,
            "battery_level": 86,
            "mode": "idle",
        }
        return CapabilityResult(ok=True, data=device_state)
```

### 6.5 Tool 注册示例

```python
from agent_core.tools.registry import ToolRegistry
from agent_core.tools.builtins.query_device_state import QueryDeviceStateTool


def register_builtin_tools(registry: ToolRegistry) -> None:
    """注册内置 Tool。"""

    registry.register(QueryDeviceStateTool)
```

### 6.6 Tool 接入 AgentFacade 的方式

开发者不应自己直接把 Tool 暴露给 OpenAI SDK，而应交给 `AgentFacade` 统一处理。

建议 `AgentFacade` 提供：

```python
from agents import Agent


class AgentFacade:
    """封装 OpenAI Agents SDK 与项目内注册表的统一入口。"""

    def __init__(self, tool_registry, skill_registry, mcp_registry) -> None:
        ...

    def build_agent(self):
        """构建主 Agent。"""
        ...
```

`AgentFacade` 内部负责：

1. 从 `ToolRegistry` 读取 Tool。
2. 从 `SkillRegistry` 读取 Skill，并同样按 Tool 处理。
3. 从 `McpRegistry` 读取 MCP server。
4. 转成 OpenAI Agents SDK 的 `function_tool(...)` 与 `Agent(...)` 需要的对象。
5. 构建主 Agent。

## 7. Skill 的具体写法

### 7.1 当前阶段 Skill 的实现原则

当前阶段不要单独做重型 `SkillRuntime`。

统一要求：

1. Skill 本质上实现为一个 `BaseTool` 子类。
2. Skill 内部组合多个 Tool、MCP、TaskGateway。
3. Skill 对外仍然只暴露一个 Tool 名字给模型。

### 7.2 推荐基类

Skill 可直接复用 `BaseTool`，只额外加一层说明模型。

```python
from pydantic import BaseModel


class SkillSpec(BaseModel):
    """Skill 元信息。"""

    name: str
    description: str
    allowed_tools: list[str] = []
    allowed_mcps: list[str] = []
    may_create_task: bool = False


class BaseSkill(BaseTool):
    """Skill 统一基类，当前阶段复用 Tool 的执行模型。"""

    skill_spec: SkillSpec
```

### 7.3 SkillRegistry 约定

```python
class SkillRegistry:
    """Skill 注册表。"""

    def register(self, skill_cls: type[BaseSkill]) -> None:
        ...

    def get(self, name: str) -> type[BaseSkill]:
        ...
```

注册原则：

1. `SkillRegistry` 只注册 `BaseSkill` 子类。
2. `AgentFacade` 最终仍把 Skill 当成 Tool 暴露给模型。
3. Skill 内部依赖由 `AgentFacade` 或依赖注入容器统一创建。

### 7.4 Skill 示例

下面是 `photo_interpret` 的推荐写法：

```python
from __future__ import annotations

from pydantic import BaseModel, Field

from agent_core.models.capability_models import CapabilityResult, ToolContext
from agent_core.skills.base import BaseSkill, SkillSpec
from agent_core.tools.base import ToolSpec


class PhotoInterpretInput(BaseModel):
    """图片解读输入参数。"""

    question: str = Field(description="用户希望基于图片回答的问题")


class PhotoInterpretOutput(BaseModel):
    """图片解读输出结构。"""

    answer: str = Field(description="基于图片内容生成的回答")


class PhotoInterpretTool(BaseSkill):
    """拍照并结合图片回答问题。"""

    spec = ToolSpec(
        name="photo_interpret",
        description="触发拍照并结合图片内容回答用户问题",
        input_model=PhotoInterpretInput,
        output_model=PhotoInterpretOutput,
        tags=["photo", "vision"],
    )
    skill_spec = SkillSpec(
        name="photo_interpret",
        description="拍照并结合图片内容回答用户问题",
        allowed_tools=["capture_photo"],
        may_create_task=False,
    )

    def __init__(self, capture_photo_tool, vision_service) -> None:
        self._capture_photo_tool = capture_photo_tool
        self._vision_service = vision_service

    async def run(self, ctx: ToolContext, input_data: PhotoInterpretInput) -> CapabilityResult:
        """执行拍照和图片理解流程。"""

        photo_result = await self._capture_photo_tool.run(ctx, self._capture_photo_tool.spec.input_model())
        if not photo_result.ok:
            return photo_result

        answer = await self._vision_service.describe(
            asset_id=photo_result.asset_refs[0],
            question=input_data.question,
        )
        return CapabilityResult(ok=True, data={"answer": answer}, asset_refs=photo_result.asset_refs)
```

注意：

1. Skill 不允许自己偷偷启动后台线程。
2. 如果流程需要长期等待，必须改成 Task。

## 9. Task 的具体写法

### 9.1 必须区分 Task 与 TaskRuntime

开发者常见错误是把 `Task` 和 `TaskRuntime` 混为一谈。

正确区分：

1. `Task`
   - 后台任务模板代码。
   - 还没启动。
2. `TaskRuntime`
   - 某个 `Task` 被创建后的实例。
   - 由 `backend-task-core` 托管。

### 9.2 必须实现的类

每个 Task 至少需要：

1. `TaskSpec`
2. `BaseTask` 子类
3. 输入模型
4. 事件产出逻辑
5. 注册代码

### 9.3 推荐模型

```python
from __future__ import annotations

from typing import Any, Literal

from pydantic import BaseModel, Field


class TaskSpec(BaseModel):
    """Task 模板定义。"""

    task_type: str
    version: str
    description: str
    input_model: type[BaseModel]
    supports_cancel: bool = True
    supports_pause: bool = False
    supports_resume: bool = False
    timeout_seconds: int = 3600


class TaskRuntime(BaseModel):
    """Task 运行实例。"""

    task_id: str
    task_type: str
    version: str
    session_id: str
    device_id: str
    state: Literal[
        "created",
        "scheduled",
        "running",
        "waiting_external",
        "completed",
        "cancelled",
        "failed",
        "timeout",
    ]
    input: dict[str, Any] = Field(default_factory=dict)
    context: dict[str, Any] = Field(default_factory=dict)
    result: dict[str, Any] | None = None
    error: dict[str, Any] | None = None
```

### 9.4 推荐基类

```python
from __future__ import annotations

from abc import ABC, abstractmethod
from typing import ClassVar

from backend_task_core.models import TaskRuntime, TaskSpec


class BaseTask(ABC):
    """所有 Task 的统一基类。"""

    spec: ClassVar[TaskSpec]

    @abstractmethod
    async def run(self, runtime: TaskRuntime, gateway) -> None:
        """运行任务主体逻辑。"""
        raise NotImplementedError

    async def on_cancel(self, runtime: TaskRuntime, gateway) -> None:
        """取消任务时的处理逻辑。"""
        return None
```

### 9.5 TaskGateway 的强制使用方式

开发者不要直接 new `TaskRuntime`，也不要直接起线程。

统一入口只能是 `TaskGateway`：

```python
class TaskGateway:
    """Task 统一访问网关。"""

    async def create_task(
        self,
        task_type: str,
        session_id: str,
        device_id: str,
        input: dict[str, object],
    ) -> TaskRuntime:
        ...

    async def query_task(self, task_id: str) -> TaskRuntime:
        ...

    async def cancel_task(self, task_id: str) -> TaskRuntime:
        ...
```

以下两种写法禁止出现：

1. Tool 里直接维护 `asyncio.create_task(...)` 作为长期任务。
2. Agent 里直接 new 一个 `TaskRuntime`。
3. 未经过 `TaskSpec.input_model.model_validate(...)` 就创建任务。

### 9.6 TaskRegistry 的注册方式

```python
class TaskRegistry:
    """Task 注册表。"""

    def register(self, task_cls: type[BaseTask]) -> None:
        ...

    def get(self, task_type: str) -> type[BaseTask]:
        ...
```

推荐注册文件：

1. `server/src/task/__init__.py`

注册示例：

```python
from backend_task_core.registry import TaskRegistry
from task.timer_task import TimerTask


def register_builtin_tasks(registry: TaskRegistry) -> None:
    """注册内置 Task 模板。"""
```

### 9.7 Task 示例

下面是 `timer_task` 的推荐骨架：

```python
from __future__ import annotations

from pydantic import BaseModel, Field

from backend_task_core.base import BaseTask
from backend_task_core.models import TaskEvent, TaskRuntime, TaskSpec


class TimerTaskInput(BaseModel):
    """计时器任务输入参数。"""

    duration_seconds: int = Field(gt=0, description="计时秒数")


class TimerTask(BaseTask):
    """最小计时器后台任务。"""

    spec = TaskSpec(
        task_type="timer_task",
        version="v1",
        description="计时器后台任务",
        input_model=TimerTaskInput,
        supports_cancel=True,
        timeout_seconds=86400,
    )

    async def run(self, runtime: TaskRuntime, gateway) -> None:
        """执行计时器任务，并在完成时发布标准事件。"""

        duration_seconds = runtime.input["duration_seconds"]
        await gateway.scheduler.sleep(duration_seconds)
        await gateway.event_bus.publish(
            TaskEvent(
                event_id=f"evt_{runtime.task_id}_completed",
                event_name="task.completed",
                task_id=runtime.task_id,
                task_type=runtime.task_type,
                session_id=runtime.session_id,
                device_id=runtime.device_id,
                priority="normal",
                payload={"duration_seconds": duration_seconds},
            )
        )
```

### 9.8 Task 事件协议

每个 Task 事件至少要包含：

1. `event_id`
2. `event_name`
3. `task_id`
4. `task_type`
5. `session_id`
6. `device_id`
7. `priority`
8. `payload`

优先级统一只允许：

1. `low`
2. `normal`
3. `high`
4. `critical`

禁止自定义成：

1. `urgent`
2. `very_high`
3. `important`

否则后续通知策略无法统一。

### 9.9 Task 允许调用什么

Task 内部允许通过统一网关调用：

1. `ToolGateway`
2. `SkillGateway`
3. `McpGateway`
4. `DeviceGateway`
5. `CameraGateway`
6. `AudioGateway`

Task 内部不允许：

1. 直接操作底层 WebSocket。
2. 直接绕开 `TaskEventBus` 发音频文案。
3. 直接改写 `agent-core` 会话上下文。

---

## 10. AgentFacade 的统一职责

`AgentFacade` 是开发者接触 `agent-core` 的主入口。

开发者不应直接在业务代码里拼装 OpenAI Agents SDK 主循环，而应通过 `AgentFacade`。

`AgentFacade` 至少要承担：

1. 收集 `ToolRegistry` 中的 Tool。
2. 收集 `SkillRegistry` 中的 Skill。
3. 收集 `McpRegistry` 中的 MCP server。
4. 构建主 Agent。
5. 提供统一的 `handle_user_turn(...)` 方法。

建议接口：

```python
class AgentFacade:
    """agent-core 统一访问入口。"""

    async def handle_user_turn(
        self,
        session_id: str,
        device_id: str,
        text: str,
        asset_refs: list[str] | None = None,
        derived_refs: list[str] | None = None,
    ) -> dict[str, object]:
        """处理一轮用户输入并返回统一结果。"""
        ...
```

`voice-runtime` 后续只依赖这个入口，不直接知道 Tool、Skill、MCP、Task 的细节。

## 11. 开发者的最小工作流

### 11.1 新增 Tool 的步骤

1. 在 `server/src/agent_core/tools/builtins/` 下新建文件。
2. 写输入模型、输出模型、`BaseTool` 子类。
3. 在工具注册入口注册。
4. 补单元测试。
5. 如果需要，被 `AgentFacade` 自动加载。

### 11.2 新增 Skill 的步骤

1. 在 `server/src/agent_core/skills/builtins/` 下新建文件。
2. 实现一个组合型 `BaseTool`。
3. 在 `SkillRegistry` 注册。
4. 补流程测试。

### 11.3 新增 MCP 的步骤

1. 在 `server/src/agent_core/mcp/adapters/` 下新建 Adapter。
2. 实现 `BaseMcpAdapter`。
3. 在 `McpRegistry` 注册。
4. 写联调说明。

### 11.4 新增 Task 的步骤

1. 在 `server/src/task/` 下新建任务模板文件。
2. 定义输入模型、`TaskSpec`、`BaseTask` 子类。
3. 在 `TaskRegistry` 注册。
4. 通过 `TaskGateway` 被 Tool 或 Task 创建。
5. 补状态机和事件测试。

## 12. 测试要求

### 12.1 Tool 测试

至少验证：

1. 输入校验是否正确。
2. 成功返回结构是否正确。
3. 失败返回结构是否正确。

### 12.2 Skill 测试

至少验证：

1. 内部组合调用顺序是否正确。
2. 某个下游 Tool 或 MCP 失败时，Skill 是否返回统一错误。

### 12.3 Task 测试

至少验证：

1. `TaskSpec` 是否正确。
2. 状态迁移是否合法。
3. 是否按预期发布标准事件。
4. `priority` 是否符合通知要求。

### 12.4 跨设备联调要求

涉及眼镜、手机、服务端三方时，文档中必须写清：

1. 服务端启动命令。
2. 眼镜端启动命令。
3. 手机端启动命令。
4. 关键协议消息。
5. 预期日志。
6. 预期现象。

## 13. 开发前自查清单

开始写代码前先确认：

1. 我新增的是 Tool、Skill、MCP 还是 Task。
2. 我是否已经确定目录和注册入口。
3. 我是否已经确定输入输出模型。
4. 我是否已经确定错误模型。
5. 如果是 Task，我是否已经确定状态机和事件协议。

## 14. 最终原则

这个框架的目标不是“让每个人都快速写出一个能跑的函数”，而是：

1. 任何人新增一个 Tool，都不用改主循环。
2. 任何人新增一个 Skill，都不用改主循环。
3. 任何人新增一个 MCP，都不用改主循环。
4. 任何人新增一个 Task，都不用改调度核心。

后续开发者如果发现自己在做下面这些事，说明已经偏离框架：

1. 在 `voice-runtime` 里硬编码某个业务能力。
2. 在 Agent 主循环里写 `if user_text contains ...`。
3. 在 Tool 里自己起长期后台线程。
4. 在 Task 里直接向设备发送自然语言文案而不发标准事件。

一旦出现这些情况，应先回到本指南，重新判断能力边界和接入方式。
