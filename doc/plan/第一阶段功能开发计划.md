# 第一阶段功能开发计划

## 1. 文档目标

本文仅关注第一阶段的功能开发工作，不重复描述架构底座本身。所有功能均默认建立在《架构开发计划》定义的统一协议、统一运行时和统一模块边界之上。

本文回答的问题是：

- 第一阶段具体要交付哪些用户可感知能力。
- 这些功能应该按什么顺序开发。
- 每个功能依赖哪些底层架构能力。
- 每个功能达到什么标准才算完成。

## 2. 第一阶段功能目标

第一阶段功能目标是完成若干条最小可用闭环，验证系统具备以下产品能力：

- 眼镜与服务器可进行语音交互
- 大模型可以调用系统内部能力
- 系统可以创建与管理后台任务
- 手机可以作为边缘计算节点参与任务
- 外部服务可以通过 MCP 方式被系统纳入任务编排

## 3. 功能开发范围

本阶段计划开发以下功能：

- 非实时语音对话
- 实时语音对话与打断
- 拍照 Skill 与图片解读
- 后台计时器任务
- 手机接入与视频流任务
- 基于 AMap MCP 的最小导航能力

本阶段不要求完整交付以下功能：

- 室外最后 10 米引导
- 红绿灯 / 盲道 / 非机动车道完整识别能力
- 完整避障与通路规划
- 用户自定义知识库
- 长期记忆完整产品化

## 4. 功能开发原则

- 先做最小闭环，再做泛化扩展。
- 先做高频核心场景，再做边缘场景。
- 功能实现必须复用既有架构，不允许绕过统一运行时形成临时主路径。
- 每个功能开发前必须先补方案文档。

## 5. 功能清单与拆解

## 5.1 功能 F1：眼镜与服务器非实时语音对话

### 目标

用户通过眼镜说话，服务器调用云端模型处理后，将语音结果返回眼镜播放。

### 用户场景

- 用户提出一个普通问题
- 眼镜录音并上传
- 服务器完成语音理解与回答
- 用户听到返回结果

### 开发内容

- 眼镜端录音触发与结束
- VAD 支持
- 音频上传与存储
- 百炼 `qwen3.5-omni-plus` 非实时调用
- 返回音频播放
- 全链路日志

### 完成定义

- 支持完整一轮语音问答
- 不要求中途打断
- 异常情况可识别并记录日志

### 验收标准

- 眼镜侧可发起至少 3 轮稳定问答
- 语音返回可正常播放
- 关键链路日志可追踪

## 5.2 功能 F2：实时语音对话与打断

### 目标

实现更自然的连续对话体验，支持用户打断当前播报。

### 用户场景

- 系统正在播报回答
- 用户中途再次说话
- 系统停止当前播报并切换到新一轮交互

### 开发内容

- 流式音频传输
- 实时语音模型接入
- 眼镜侧执行总线打断机制
- 播放优先级控制
- 对话轮次切换与上下文控制

### 完成定义

- 支持边播报边被打断
- 打断后系统进入新的交互轮次
- 不因打断导致执行状态混乱

### 验收标准

- 支持至少 3 次连续打断测试
- 无明显状态错乱
- 打断后仍能正常返回新回答

## 5.3 功能 F3：拍照 Skill 与图片解读

### 目标

用户通过自然语言触发图片理解，系统自动调用拍照 Skill 完成解读。

### 用户场景

- 用户说“帮我看一下前面有什么”
- 模型判断需要拍照
- 系统控制眼镜拍照
- 图片回传服务器
- 云端模型解读图片并播报

### 开发内容

- 拍照 Skill
- 眼镜拍照命令
- 图片上传
- 图片理解 Prompt 设计
- Agent 调用 Skill 的流程验证

### 完成定义

- 无需写死关键词分支也可触发拍照
- 模型能够在上下文中做出 Tool 选择

### 验收标准

- 至少覆盖 2 类自然语言表达触发
- 图片解读结果可正常播报

## 5.4 功能 F4：后台计时器任务

### 目标

验证后台任务体系可支撑长生命周期任务。

### 用户场景

- 用户说“帮我计时三分钟”
- Agent 创建计时器任务
- 任务在后台运行
- 时间到后系统主动提醒用户

### 开发内容

- 后台任务管理 Skill
- 计时器任务模板
- 任务创建、查询、结束能力
- 任务完成通知

### 完成定义

- 任务可异步创建
- 任务状态可查询
- 任务结束可主动通知

### 验收标准

- 能稳定完成创建、查询、结束三类操作
- 任务提醒链路闭环

## 5.5 功能 F5：手机接入与视频流任务

### 目标

验证手机作为边缘执行节点参与任务处理。

### 用户场景

- 用户或 Agent 发起手机视频流相关任务
- 服务器协调眼镜与手机建链
- 眼镜视频流传给手机
- 手机端页面实时回显

### 开发内容

- 手机设备注册
- 手机与眼镜绑定
- 直连建链
- 视频流上传与回显页面
- 建链状态和任务状态回传

### 完成定义

- 完成一次稳定视频流演示闭环
- 服务器可感知建链成功与失败

### 验收标准

- 视频流可被手机稳定接收
- 页面可实时回显
- 链路异常可记录

## 5.6 功能 F6：基于 AMap MCP 的最小导航能力

### 目标

验证 MCP + Agent + Task 的综合能力。

### 用户场景

- 用户说“导航去桂林路地铁站”
- 模型与用户确认导航参数
- 系统调用 AMap MCP 获取路线
- 系统播报导航信息

### 开发内容

- AMap MCP 接入
- 导航参数澄清
- 导航任务原型
- 状态播报策略

### 完成定义

- 可以完成一次最小导航请求
- 支持参数确认和结果播报

### 验收标准

- 至少跑通一个真实目的地样例
- 导航参数确认流程完整

## 6. 功能开发顺序

建议按照以下顺序推进：

1. 非实时语音对话
2. 实时语音对话与打断
3. 拍照 Skill 与图片解读
4. 后台计时器任务
5. 手机接入与视频流任务
6. AMap 最小导航能力

排序依据：

- 先验证最核心交互能力
- 再验证 Agent 调度能力
- 再验证后台任务能力
- 最后验证跨端协同和外部服务编排能力
