# 架构与功能依赖矩阵

## 1. 文档目标

本文用于说明“架构开发工作”和“功能开发工作”之间的依赖关系，帮助排期、分工和验收。

阅读方式：

- 如果关心底座建设，看《架构开发计划》。
- 如果关心业务闭环，看《第一阶段功能开发计划》。
- 如果关心功能什么时候能开始做、依赖哪些前置条件，看本文。

## 4. 依赖解读

### 4.1 哪些功能可以在架构未完全完成时提前启动

以下功能可以在部分架构能力具备后尽早开始：

- F1 非实时语音对话
- F2 实时语音对话与打断

原因：

- 这两个功能主要依赖眼镜与服务器主链路，不依赖手机和复杂任务体系。

### 4.2 哪些功能必须等架构框架成熟后再启动

以下功能建议不要过早启动：

- F3 拍照 Skill 与图片解读
- F4 后台计时器任务
- F6 AMap 最小导航能力

原因：

- 这些功能若在 Agent / Skill / Task / MCP 框架未稳定前就直接实现，容易产生绕过架构的临时代码。

### 4.3 哪些功能强依赖手机侧底座

- F5 手机接入与视频流任务

原因：

- 该功能本质上不是单一业务功能，而是跨端协同能力验证，必须以手机接入、绑定关系和建链底座为前提。

## 5. 推荐推进顺序

推荐采用“架构先行、功能穿插验证”的方式推进。

### 5.1 第一步：完成最小主链路架构

优先完成：

- A1 统一协议与数据模型
- A2 三端工程骨架
- A3 设备注册与连接管理
- A4 消息路由与追踪
- A5 眼镜感知总线
- A6 眼镜执行总线
- A14 日志与测试底座

此时可启动：

- F1 非实时语音对话

### 5.2 第二步：增强语音交互能力

在第一步基础上增强：

- 流式传输能力
- 眼镜执行打断策略

此时可启动：

- F2 实时语音对话与打断

### 5.3 第三步：完成 Agent / Skill / Task 核心框架

优先完成：

- A7 Agent 运行时框架
- A8 Skill 注册与执行框架
- A10 后台任务运行时框架

此时可启动：

- F3 拍照 Skill 与图片解读
- F4 后台计时器任务

### 5.4 第四步：完成手机侧底座

优先完成：

- A11 手机接入底座
- A12 手机本地任务运行时
- A13 手机与眼镜绑定 / 建链底座

此时可启动：

- F5 手机接入与视频流任务

### 5.5 第五步：完成外部服务适配底座

优先完成：

- A9 MCP 接入框架

此时可启动：

- F6 AMap 最小导航能力

## 6. 分工建议

如果后续需要多人并行推进，建议按以下方式切分：

- 架构线：负责 A1-A14
- 功能线：负责 F1-F6
- 联调线：负责集成测试、联调脚本、演示闭环、日志验证

为了避免返工，建议遵循两条规则：

- 功能开发不得跳过对应前置架构能力。
- 架构能力在未给出接口前，功能侧不要自行定义临时接口作为长期方案。

## 8. 结论

将架构开发和功能开发分开后，可以形成更清晰的推进方式：

- 《架构开发计划》负责定义“底座先做什么”。
- 《第一阶段功能开发计划》负责定义“业务先做什么”。
- 本文负责定义“业务何时能做、依赖什么底座”。

这三份文档组合后，可以同时支撑技术设计、研发排期和阶段验收。
