根据对业界资料（包括 Anthropic 官方发布、技术社区分析及主流 AI 平台文档）的综合检索与整理，以下是大模型技术中 **Tools**、**Skills**（Anthropic 定义）和 **MCP** 三种工具的严格定义：

---

### 1. **Tools（工具）**

**通用定义**：  
在大语言模型（LLM）领域，**Tools** 是指可供模型调用以完成特定外部任务的函数或接口。这些工具通常封装了某种原子能力，例如调用 API、读取文件、执行代码、查询数据库等。

- **特点**：
  - 原子性：每个 Tool 通常只完成一个明确、单一的功能。
  - 可编程：由开发者定义输入输出格式，模型通过结构化方式（如 JSON）调用。
  - 通用性：不限定于某一厂商，OpenAI、Google、Meta 等均有类似概念（如 OpenAI 的 Function Calling）。

- **典型示例**：  
  OpenAI 的 `function` 工具、LangChain 中的 `Tool` 抽象、Hugging Face Agents 中的工具集。

> 注意：**“Tools” 是一个通用术语，并非某一家公司的专属标准**。

---

### 2. **Skills（技能）— Anthropic 定义**

**官方定义（来自 Anthropic）**：  
> “Skills are folders of instructions, scripts, and resources that Claude loads dynamically.”  
> （技能是包含指令、脚本和资源的文件夹，Claude 可在运行时动态加载。）

- **核心特征**：
  - **模块化封装**：每个 Skill 是一个标准化目录，必须包含 `SKILL.md` 元数据文件，描述其用途、使用方式、输入输出规范等。
  - **渐进式披露（Progressive Disclosure）**：仅在任务相关时才加载上下文，避免污染模型的主上下文窗口。
  - **可执行性**：除文本指令外，还可包含可执行脚本（如 Python 脚本），使模型不仅能“知道怎么做”，还能“实际执行”。
  - **专业性**：面向特定领域任务（如生成品牌合规的 PPT、处理 Excel 表格、前端 UI 设计），强调“高工艺感”和“生产级输出”。

- **定位**：  
  Skills 不是简单的函数调用，而是**任务执行手册 + 执行环境**的结合体，旨在将人类专家的工作流固化为可复用的 AI 能力单元。

- **发布时间**：  
  Anthropic 于 **2025 年 12 月 18 日**正式将 Agent Skills 发布为**开放标准**，并推出 [agentskills.io](https://agentskills.io) 规范文档，获得 Microsoft、OpenAI、GitHub 等广泛支持。

---

### 3. **MCP（Model Context Protocol，模型上下文协议）**

**提出者**：Anthropic（2024 年 11 月首次发布）

**官方定义**：  
> “MCP is an open standard that standardizes how applications provide context to large language models.”  
> （MCP 是一种开放标准，用于标准化应用程序如何向大语言模型提供上下文。）

- **本质**：  
  MCP 是一个**通信协议**，而非具体功能模块。它定义了 LLM 与外部数据源/工具之间交互的**统一接口**，类似于“AI 领域的 USB-C”。

- **架构**：
  - 采用 **客户端-服务器（Client-Server）模型**。
  - **Host（主机）**：运行 LLM 的应用（如 Claude Desktop）。
  - **MCP Server**：轻量级服务，暴露本地或远程资源（如文件系统、Slack、GitHub）。

- **核心目标**：
  - 解决“数据孤岛”问题，让模型安全访问外部上下文。
  - 实现工具的**动态发现与即插即用**。
  - **不规定任务逻辑**，只负责“连接”和“上下文传递”。

- **与 Tools/Skills 的关系**：  
  MCP 是**底层连接层**，而 Tools 或 Skills 是**上层能力单元**。MCP 可为 Skill 提供所需的数据源访问能力。

---

### 总结对比

| 维度 | Tools | Skills（Anthropic） | MCP |
|------|-------|---------------------|-----|
| **性质** | 函数/接口 | 模块化能力包（含指令+脚本） | 通信协议 |
| **粒度** | 原子操作 | 复合任务流程 | 连接通道 |
| **是否标准** | 各家自定义 | Anthropic 提出的开放标准 | Anthropic 提出的开放标准 |
| **是否包含执行逻辑** | 否（仅调用） | 是（含脚本与资源） | 否（仅传输上下文） |
| **典型用途** | 获取天气、发邮件 | 生成品牌PPT、自动化测试 | 连接数据库、访问Slack |

---

以上定义均基于对 Anthropic 官方发布、GitHub 仓库（如 [anthropics/skills](https://github.com/anthropics/skills)）、[modelcontextprotocol.io](https://modelcontextprotocol.io) 及主流技术媒体（CSDN、稀土掘金、腾讯科技等）的综合分析。
