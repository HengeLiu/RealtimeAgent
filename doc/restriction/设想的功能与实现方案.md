# 功能与设想的大致实现方案

注意每个功能的实现方案都是设想中的，并不是真的明确应该这样实现，只是作为开发代码的参考。

# 室内主动系统 （重要等级：高 核心功能）

1. 语音发起寻找常见物体，使用现有代码基于YOLO的实现
   方案：将现有实现封装成工具，由用户关键词触发（例如'帮我找一下'、'找一下'、'寻找'），或大模型助手调用工具触发任务（例如'我的手机放到哪里了'）。大模型助手运行在服务器端，服务器端给眼镜和手机各发送一条开启任务的指令，然后眼镜和手机自行建立一条长连接，可以基于websocket或其他更合适的，眼镜和手机实现直接通讯。眼镜传输图片给手机，手机接收到图片后使用YOLO模型完成检测，然后按照当前已经实现的逻辑输出语义播报的指令发送给眼镜，眼镜收到播报指令后继续发送下一帧图片给手机，手机继续计算指令，如此循环，指导手机发出结束的指令，断开连接，完成任务。并且任务持续期间需要持续发送任务的状态给服务器，服务器会将其记录在文件中供大模型助手查询。
2. 阅读纸质书籍/药品说明书
   方案：同样用户关键词触发或大模型助手调用工具触发该任务。服务器识别到是阅读任务的时候，立刻发送拍照指令到眼镜，眼镜拍照将图片发送回服务器，智能体接收到图片后调用云端的大模型（全模态大模型，例如qwen3.5-omini）进行解读，云端大模型流式返回音频给服务器，服务器将收到的音频发送到眼镜端完成流式播放。

# 室外主动系统（重要等级：高 核心功能）

1. 实现点到点的引导导航
   方案：同样用户关键词或大模型助手触发导航任务，例如用户说“我想去桂林路地铁站”、“我想去最近的书店”，大模型自主与用户交互，直到确认用户是要导航到确切的位置点，例如用户问“我想要去最近的书店”，大模型查询书店位置，并自主与用户交互，确认用户要去哪一个书店，然后将确切的位置发送给高德地图MCP服务，获取导航路径，与用户确认后开启导航任务。

   开始导航后，手机会持续发送高德SDK提供的纠偏信息，以及导航路线信息。
2. 寻找通路（毫米波/视觉算法，引路）
   方案：同样用户关键词或大模型助手触发寻找通路任务，例如用户说“帮我引路”、“前面能过去吗”、“我该怎么走过去”等，技术方案与寻找物体类似。
3. 红绿灯盲道非机动车道等关键因素的识别（yolo）
   方案：不确定具体实现方式，但任务的形式与寻找物体、寻找通路类似，都是做成Skills，使用统一的方式与服务器、眼镜进行通讯，内部实现细节目前为止。
4. 室外最后10米的引导
   方案：不确定

   问题：在完成导航任务后自动发起，或者用户主动发起，区别于寻找物体，这里是对相机中的某个物体进行点到点导航/通路检测，不同于单纯的导航和寻找通路，比较有难度。

# 用户自定义系统（重要等级：高 核心功能）

1. 用户可以定时，比如定时三秒检查一次图中某东西的变化（参数设定时间与提示词）
   方案：同样用户关键词或大模型助手触发，设计一个能在后台运行的Skill，每隔一段时间自动发送一条拍照指令给眼镜，获取图片后自动完成检查，并发送通知给眼镜或者主智能体。发起定时任务应当作为一个通用能力，任何类型的其他能力（在服务器上的Skills）都可以由该定时任务调起。
2. 用户可以修改提示词     -写skills    用户可以自定义知识库    用户设置记忆时长
   方案：在我们场景下，因为只有一个会话，所以不需要做会话隔离，但也会导致上文持续增加。所以需要每隔一段时间对上文进行压缩，并且提取记忆保存到记忆库中。

   问题：在我们的场景下为什么会需要知识库？

1. 提示音+震动  供用户选择
   方案：将眼镜的设置功能封装成Skill，可以由用户主动发起或大模型调用。
