## 总体结论

当前仓库已经从早期三端 Demo 演进到“服务端运行时 + iOS 手机端 + ESP32 眼镜端 + Python SDK 原型 + 官方 example”的混合状态。

当前服务端实现已经完成 SDK 化迁移：

1. [sdk/python/app/main.py](/Users/elio/dev/llm-project/OpenAIglassesDemo_2/sdk/python/app/main.py)：SDK 内真实服务端入口，承载 HTTP、控制 WebSocket、音频 WebSocket 和运行时装配。

3. [example/server/main.py](/Users/elio/dev/llm-project/OpenAIglassesDemo_2/example/server/main.py)：SDK 官方示例入口，会通过 `OpenAIGlassesSDK` 注册 `find_object` 示例 Tool、Task、PhoneProcessor 和 PhoneTask，再装配真实服务端。

## 需要注意的真实边界

1. 普通对话路径虽然使用流式模型接口，但普通文本 delta 不是完整端到端透传到 TTS 的真流式；图片解读和部分回调路径更接近流式体验。
2. 单次抓拍当前是控制面请求加 JPEG 回传，不是持续 `/ws/camera` 二进制媒体流。
3. `find_object` 当前应统一视为 SDK 官方样例能力，相关实现优先看 [example/capabilities/find_object](/Users/elio/dev/llm-project/OpenAIglassesDemo_2/example/capabilities/find_object) 和 [example/phone/ios](/Users/elio/dev/llm-project/OpenAIglassesDemo_2/example/phone/ios)。
4. `doc/experimental` 下内容是方案调研或 demo，不代表当前主链路已经全部采用。
5. `origin-project` 是旧项目参考，不是当前运行主工程。

## 跨设备联调顺序

1. 启动服务端，确认 `/api/health` 和 `/api/runtime/devices` 正常。
2. 启动 iOS 手机端，确认手机注册、心跳、局域网地址和 camera sink 地址进入运行态。
3. 启动 ESP32 眼镜端，确认眼镜注册、心跳、语音会话打开和音频上行连接。
4. 触发语音对话，观察服务端 `voice_runtime`、`agent_core`、TTS、`/stream.wav` 日志。
5. 触发 `capture_photo` 或通过 SDK 官方示例入口触发 `start_find_object`，观察服务端任务事件、眼镜视频/抓拍控制消息、手机端视频帧与检测结果。

更细的真机前检查和日志观察点见 [SDK真机联调前检查与联调步骤.md](/Users/elio/dev/llm-project/OpenAIglassesDemo_2/doc/sdk-design/SDK真机联调前检查与联调步骤.md)。
